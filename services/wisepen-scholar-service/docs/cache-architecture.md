# 缓存与标题匹配

服务共用一个 Redis 客户端，业务缓存只有三个边界：

| 边界 | 内容 | 默认有效期 |
| --- | --- | --- |
| query | 按来源和查询条件保存候选列表及其顺序；命中后仍执行出口投影 | 600 秒 |
| paper | 按来源保存内部完整 Paper 或确认未找到；内部维护标题索引和 Unpaywall PDF 正负结果 | 正结果 86400 秒，负结果 3600 秒 |
| discover | 按来源、领域、日/周/月窗口、排序和候选数保存发现结果及窗口信息 | 900 秒 |

paper 使用 `scholar:paper:paper-v3:<collection-alias>:*`，来源身份、标题索引和 Unpaywall 补充事实在内部隔离。旧 lookup、title、PDF key 不再读取，等待原 TTL 自然过期。S2 排队、配额和回执属于共享运行协调状态，保持原机制。

## 查询流程

match 将归一化后的完整标题去重，并按输入位置返回结果：

1. 标题索引定位已有来源论文，按配置顺序选取基础事实，组装已有 metadata 和 PDF。只有身份、没有正文的记录不算命中；HF 列表概要也不写成完整来源论文。
2. 未解决项查询本地标题库，直接复用返回的 Paper，补齐既有 arXiv DOI，写入 paper 缓存。不会再按身份重查本地库。
3. 仍未解决的项交给 Crossref；唯一 DOI 通过 lookup 获取和补全，完整来源事实及 PDF 补救结果写入同一个 paper 边界。请求标题与正式标题不同时，仍保留请求标题索引。
4. 同名歧义不任选一篇。失败按项返回，缓存和本地已成功的项保留；原顺序和重复位置不变。

lookup 先读取各来源缓存，再执行未解决项的来源请求。通用来源互相替代；来源未找到只约束该来源，不构成全局负缓存。缓存命中不再发起领域或 PDF 外部补全；新的来源结果仍执行既有领域富化和 PDF 补救。

## 事实与失效

缓存保存投影前的完整作者、来源 metadata 和已取得的补充事实，公共响应才执行作者裁剪和 metadata 投影。query 保持自己的候选快照，不改为论文 ID 列表。Unpaywall 的未找到与缓存未命中明确区分，避免反复请求。

离线同步按 `invalidate(source, identifiers)` 失效对应来源及其身份别名；其他来源与 Unpaywall 结果保留。残留标题索引缺少正文时继续回退。来源缓存和 query/discover 不按用户或凭证隔离；HF/OpenAlex 搜索与 HF 发现的 BYOK 准入仍先于缓存读取，S2 在途请求和配额继续按既有凭证语义隔离。
