# 标题树能力

标题树只读取当前已发布 Document 的 Section 结构，不访问 Qdrant、Neo4j，也不调用 LLM。首版只保留两个动作：

- `neighborhood`：按一批全局 `section_id` 查看各自邻域；
- `global_outline`：按 `resource_id` 查看整份文档的有限深度大纲。

删除 `hit_projection`。检索命中哪些 Section 已经由混合检索结果披露；需要观察这些命中的目录位置时，调用方把去重后的 Section ID 一次性传给批量 `neighborhood` 即可。标题树不再合并多命中窗口，也不维护 `matched` 标签。

## 1. Section ID 前提

Common `section_id` 只在一次内容解析结果内使用。RAG 入库时将其重写为：

```text
rsec_<hash(resource_id, content_revision, common_section_id)>
```

因此，RAG 暴露的 Section ID 在所有资源和 revision 中全局唯一。邻域请求只需要 `section_ids`，不再要求调用方先按 `resource_id` 分组。服务通过 Section ID 批量定位对应 active Document，再按资源批量执行 ACL 校验。

这个 ID 是不透明标识，调用方和 application 都不能从字符串中解析 `resource_id` 或 revision；定位必须走仓储索引。

旧 revision 的 Section ID 不得解析到新 revision。active 切换后，旧 ID 统一按不可见/不存在处理。

## 2. 统一目录语言

目录本身使用 Markdown 缩进文本，不把树递归编码为 JSON。每个可继续导航的普通节点格式如下：

```text
- 标题 {#section_id} [+N] (字数, p.页码) [Anchor]
```

字段按实际存在情况展示：

- `{#section_id}` 是后续邻域或 Section 读取的入口；
- `[+N]` 表示该节点还有 N 个直属孩子没有在本次视图中展开；
- 字数是该 Section 直属正文长度，不包含子 Section；
- 页码和 Anchor 由 Section 坐标与 Common `Page`、`Anchor` 的区间重叠计算。

`[+N]` 的计算规则始终相同：

```python
hidden = len(real_children) - len(shown_children)
```

只保留纵向 `[+N]`。删除 `TreeGap` 和 `⋯ [+N]`：批量邻域的每个 Section 独立返回一个连续兄弟窗口，不再把多个命中窗口合并成一棵投影森林，因此没有需要表达的中间断层。

## 3. 批量邻域

### 3.1 请求

```json
{
  "section_ids": ["rsec_a1", "rsec_b7"],
  "sibling_steps": 1
}
```

- `section_ids` 必填、去重后批量处理；可以来自不同资源；
- `sibling_steps` 表示 current 前后最多展示多少个直属兄弟，建议范围为 0 到 5；
- 结果顺序与请求中首次出现的 Section ID 顺序一致。

### 3.2 结果

每个结果把当前 Section 的定位信息作为普通 JSON 字段，把目录视图放在单独的 `outline` 字符串中：

```json
{
  "items": [
    {
      "resource_id": "doc_llama3_spec",
      "section_id": "rsec_a1",
      "title": "1.2 注意力机制演进",
      "section_path": "1. 核心架构与设计 > 1.2 注意力机制演进",
      "char_count": 8600,
      "page_range": "4-8",
      "anchor_labels": ["表1"],
      "outline": "- 1. 核心架构与设计 {#rsec_parent} (2100字, p.2-3)\n  - 1.1 背景与设计动机 {#rsec_prev} (2300字, p.3)\n  - 1.2 注意力机制演进 [C] (8600字, p.4-8) [表1]\n    - 1.2.1 标准MHA基础 {#rsec_child_1} (1400字, p.4-5)\n    - 1.2.2 GQA详解与实现 {#rsec_child_2} [+2] (3200字, p.5-7) [图2]\n  - 1.3 激活函数与FFN优化 {#rsec_next} [+3] (1900字, p.9)"
    }
  ]
}
```

JSON 外层只负责告诉调用方“当前看的是谁”：资源、Section ID、标题路径和轻量元信息。`outline` 才负责表达局部树。

current 在 `outline` 中用 `[C]` 桥接到外层字段，不重复 `{#section_id}`。这样同一个 ID 不会在相邻位置出现两次；父、兄弟和孩子仍保留 `{#section_id}`，因为它们是下一次导航或读取的入口。

### 3.3 展开规则

每个请求 Section 独立生成一个邻域：

1. 如果 current 有直属父节点，以父节点作为目录根；没有父节点时以 current 自身为根。
2. 展示 current 前后各 `sibling_steps` 个直属兄弟，兄弟窗口必须连续并按 Common `ordinal` 排序。
3. 展示 current 的所有直属孩子，不继续展开孙节点；孩子若仍有直属孩子，使用 `[+N]`。
4. 兄弟不展开孩子；兄弟若有直属孩子，使用 `[+N]`。
5. current 使用 `[C]`，不展示自己的 `{#section_id}`；current 的独立定位字段始终在同一个结果项中返回。
6. 不返回 `previous_linear`、`next_linear`、`matched`、命中分数、offset 或 span。

批量请求不是合并森林。即使两个 Section 属于同一资源、邻域窗口互相重叠，也分别返回两个 `items`，避免为了去重引入新的树合并语义。

## 4. 全局大纲

全局大纲没有 Section 入口，所以仍然按 `resource_id` 调用：

```json
{
  "resource_id": "doc_llama3_spec",
  "max_level": 2
}
```

结果同样用字符串表达目录：

```json
{
  "resource_id": "doc_llama3_spec",
  "outline": "- 1. 核心架构与设计 {#rsec_1} (2100字, p.2-3)\n  - 1.1 背景与设计动机 {#rsec_1_1} [+2] (2300字, p.3)\n  - 1.2 注意力机制演进 {#rsec_1_2} [+3] (8600字, p.4-8) [表1]\n- 2. 训练与部署 {#rsec_2} [+4] (1800字, p.10-12)"
}
```

从顶层 Section 开始递归，只展示 `section.level <= max_level` 的节点。达到边界且仍有孩子时，按统一规则显示 `[+N]`。全局大纲不使用 `[C]`，也不存在兄弟窗口和横向 gap。

## 5. 仓储与 ACL

Mongo 对 `document_revisions.structure.sections.section_id` 建立索引。批量邻域的读取顺序是：

```text
section_ids
  -> 一次查询定位候选 Document revision
  -> 批量读取对应 resource_index_states
  -> 只保留 section 所在 revision 仍为 applied 的 Document
  -> 批量读取并校验 ResourceAcl
  -> 在内存中构建各自邻域
```

同一 Document 在一次请求中只加载一次。无权资源、旧 revision ID 和不存在的 Section 对外使用同一种不可见错误，不能通过标题、路径或批量结果差异泄露资源存在性。

全局大纲按 `resource_id` 读取 active Document，并按请求资源批量读取一次本地 ACL 快照；不在返回前重复读取同一份 ACL。

## 6. 验收标准

- 标题树只有批量 `neighborhood` 和 `global_outline`，不存在 `hit_projection`。
- 批量邻域请求只依赖全局 `section_ids`，允许一次跨多个资源调用。
- 每个邻域结果使用普通 JSON 字段描述 current，目录只放在一个 Markdown `outline` 字符串中。
- current 在 outline 中标记 `[C]` 且不重复自身 ID；其他节点保留 `{#section_id}`。
- `[+N]` 只表示未展示的直属孩子，等于真实孩子数减去展示孩子数。
- 不存在 `TreeGap`、`⋯ [+N]`、`matched`、线性前后节点或投影森林合并算法。
- 同一批次按 Section ID 定位 active revision、批量判权，同一 Document 只加载一次。
- 所有节点按 Common `ordinal` 稳定排序，不暴露 offset、span 或内部结构模型。
