# 读取能力

读取能力只负责从当前已发布 `Document.raw_content` 中读取确定内容。它不做检索、排序、图谱回查、动态父块构建或缓存。

RAG 只提供两种读取方式：按 Page 读取和按 Section 读取。不提供任意字符 Range 读取，也不向调用方返回 `SourceSpan`。Common 的坐标仍用于服务内部定位正文，但它们不是读取接口契约。

同一个请求读取多个 Page 或 Section 时，只加载一次当前 `Document`，随后在内存中完成定位和取文。

## 1. 按 Page 读取

### 1.1 请求与结果

```python
class ReadPagesRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    page_labels: tuple[str, ...] = Field(min_length=1, max_length=20)


class ReadPageItem(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    page_label: str
    content: str


class ReadPagesResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    pages: tuple[ReadPageItem, ...]
```

示例：

```json
{
  "resource_id": "doc_llama3_spec",
  "pages": [
    {
      "page_label": "3",
      "content": "第三页的完整原文……"
    },
    {
      "page_label": "A-1",
      "content": "附录页 A-1 的完整原文……"
    }
  ]
}
```

处理规则：

1. 使用 Common `Page.page_label` 匹配页面，并在内部按 `Page.source_span` 从 `raw_content` 取出完整页面。
2. `page_label` 是字符串，可能是 `"3"`、`"iii"` 或 `"A-1"`，不能强制转换为整数。
3. 多个 Page 按请求顺序返回，不重新排序、不合并。
4. 未找到的页标签明确报错，不能返回空字符串冒充空白页。
5. 页面正文保持原样，不截断、不改写。

## 2. 按 Section 读取

Section 读取支持直属正文和递归子树两种模式。无论使用哪种模式，每个节点的 `content` 都只表示该 Section 自己的直属正文；递归模式通过 `children` 表达层级，不把父节和全部子节拼成一段无法区分结构的文本。

### 2.1 请求与结果

```python
class SectionReadMode(StrEnum):
    DIRECT = "direct"
    RECURSIVE = "recursive"


class ReadSectionsRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    section_ids: tuple[str, ...] = Field(min_length=1, max_length=20)
    mode: SectionReadMode = SectionReadMode.DIRECT
    max_depth: int = Field(default=1, ge=0)



class ReadSectionItem(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    section_id: str
    section_path: str
    content: str
    children: tuple["ReadSectionItem", ...] = ()


class ReadSectionsResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    sections: tuple[ReadSectionItem, ...]
```

`section_path` 使用 `" > ".join(section.section_path)` 格式，例如 `"模型架构 > 注意力机制 > GQA"`。它用于展示完整标题路径；层级关系以 `children` 为准，调用方不能通过拆分字符串恢复树结构。

### 2.2 `DIRECT` 模式

`DIRECT` 只读取请求中明确指定的 Section。每个 Section 的 `content` 由 Common `Section.content_spans` 按原文顺序读取，再用 `"\n\n".join(...)` 连接，不包含子 Section 正文；`children` 为空并在序列化时省略。这个组合方式可以直接参考旧代码 `readSections`，各段内部原文不做修改。

```json
{
  "resource_id": "doc_llama3_spec",
  "sections": [
    {
      "section_id": "sec_1_2",
      "section_path": "模型架构 > 注意力机制",
      "content": "注意力机制这一节自己的正文……"
    }
  ]
}
```

### 2.3 `RECURSIVE` 模式

`RECURSIVE` 把每个请求 Section 作为一棵返回树的根，并按 `max_depth` 读取后代。请求 Section 的深度记为 0，直属孩子为 1，孙节点为 2；只返回深度小于等于 `max_depth` 的节点。`max_depth=0` 时只返回根 Section。每个节点仍只返回自己的直属正文，因此不会重复内容。`DIRECT` 模式不使用 `max_depth`。

下面的示例使用 `max_depth=2`，所以返回请求 Section、直属孩子和孙节点：

```json
{
  "resource_id": "doc_llama3_spec",
  "sections": [
    {
      "section_id": "sec_1_2",
      "section_path": "模型架构 > 注意力机制",
      "content": "注意力机制这一节自己的正文……",
      "children": [
        {
          "section_id": "sec_1_2_1",
          "section_path": "模型架构 > 注意力机制 > MHA",
          "content": "MHA 的正文……"
        },
        {
          "section_id": "sec_1_2_2",
          "section_path": "模型架构 > 注意力机制 > GQA",
          "content": "GQA 的正文……",
          "children": [
            {
              "section_id": "sec_1_2_2_1",
              "section_path": "模型架构 > 注意力机制 > GQA > 实现细节",
              "content": "实现细节的正文……"
            }
          ]
        }
      ]
    }
  ]
}
```

### 2.4 Section 处理规则

1. 所有 `section_id` 必须属于当前 Document；不存在的 ID 明确报错。
2. 多个请求 Section 按请求顺序成为 `sections` 中的根；同一棵树内的孩子按 Common `Section.ordinal` 排序。
3. `DIRECT` 不自动读取父、子或兄弟 Section。
4. `RECURSIVE` 只沿真实 `parent_section_id` 递归，并在 `max_depth` 指定的层级停止，不根据标题文本猜测层级。
5. 如果请求同时包含祖先和它的后代，二者仍按请求分别作为根返回。这种重复由调用方输入造成，服务不擅自删除请求项。
6. 正文不设置字符或 token 上限，不截断、不摘要、不改写。

## 3. ACL 与错误边界

两种读取都先调用当前 `ResourceAcl.can_read(permission_scope)`。读取 Document 后、返回正文前再次确认权限没有被撤销。无权访问和资源不存在对外使用统一的不可见错误，避免泄露资源是否存在。

读取能力不判断旧代码中的结构模式，只检查当前 Document 是否存在请求所需的真实 Page 或 Section。没有标题树的文档不能按 Section 读取，但只要存在 Page，仍然可以按 Page 读取。

## 4. 不属于读取能力的行为

- 不提供任意 Range 读取，也不接受或返回字符坐标。
- 图谱 Evidence 回查在图谱检索内部完成。
- 动态父块构建属于混合检索和图谱检索。
- 标题树搜索、展开和邻域查看属于标题树能力。
- 上下文预算、内容截断和摘要属于调用方。
- 本次重构不增加 Redis 整资源缓存；Mongo 当前 Document 是权威来源。

## 5. 验收标准

- 只有 Page 和 Section 两种读取方式，不存在 Range 读取接口。
- Page 结果只有 `resource_id` 和由 `page_label/content` 组成的列表。
- Section 结果只有 `resource_id` 和由轻量 Section 节点组成的列表。
- Section 节点只暴露 `section_id`、格式化后的完整 `section_path`、`content` 和嵌套 `children`。
- `DIRECT` 只返回所请求 Section 的直属正文；`RECURSIVE` 用嵌套 children 返回不超过 `max_depth` 的子树。
- 接口不暴露 `SourceSpan`、offset 或 `content_revision`。
- 批量读取只加载一次 Document，并保持请求根顺序和原文子节点顺序。
- 返回正文不扩展、不合并、不截断、不改写。
- ACL 在读取前和返回前均被核验。
