# 读取能力

读取能力只负责从当前已发布 `Document.raw_content` 中读取确定内容。它不做检索、排序、图谱回查、动态父块构建或缓存。

RAG 只提供两种读取方式：按 Page 读取和按 Section 读取。不提供任意字符 Range 读取，也不向调用方返回 `SourceSpan`。Common 的坐标仍用于服务内部定位正文，但它们不是读取接口契约。

同一个请求读取多个 Page 时只加载一次当前 Document。Section ID 在 RAG 中全局唯一，Section 批量读取允许跨资源；实现先批量定位 Document，同一 Document 在一次请求中仍只加载一次。

## 1. 按 Page 读取

### 1.1 请求与结果

```python
class ReadPagesRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    page_labels: tuple[str, ...] = Field(min_length=1, max_length=20)


class ReadPageItem(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    page_label: str
    content: str


class ReadPagesResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    pages: tuple[ReadPageItem, ...]
```

示例：

```json
{
  "resource_id": "doc_llama3_spec",
  "pages": [
    {
      "page_label": "3",
      "content": "第三页的完整原文……"
    },
    {
      "page_label": "A-1",
      "content": "附录页 A-1 的完整原文……"
    }
  ]
}
```

处理规则：

1. 使用 Common `Page.page_label` 匹配页面，并在内部按 `Page.source_span` 从 `raw_content` 取出完整页面。
2. `page_label` 是字符串，可能是 `"3"`、`"iii"` 或 `"A-1"`，不能强制转换为整数。
3. 多个 Page 按请求顺序返回，不重新排序、不合并。
4. 未找到的页标签明确报错，不能返回空字符串冒充空白页。
5. 页面正文保持原样，不截断、不改写。

## 2. 按 Section 读取

Section 读取支持直属正文和递归子树两种模式。`DIRECT` 面向标题树导航，返回轻量 Section 列表；`RECURSIVE` 面向一次性打包阅读，返回带 Markdown 标题层级的完整文本，不再返回子节点 JSON。

### 2.1 请求与结果

```python
class SectionReadMode(StrEnum):
    DIRECT = "direct"
    RECURSIVE = "recursive"



class ReadSectionsRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    section_ids: tuple[str, ...] = Field(min_length=1, max_length=20)
    mode: SectionReadMode = SectionReadMode.DIRECT
    max_depth: int = Field(default=1, ge=0)



class ReadSectionItem(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    section_id: str
    section_path: str
    content: str


class ReadSectionsResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    sections: tuple[ReadSectionItem, ...]
```

请求不再携带 `resource_id`。RAG Section ID 由 `resource_id + content_revision + Common section_id` 确定性生成，仓储可以按一批 ID 定位各自的 active Document。每个返回项单独披露 `resource_id`，因为同一批请求可以包含多个资源。

`section_path` 使用 `" > ".join(section.section_path)` 格式，例如 `"模型架构 > 注意力机制 > GQA"`。它用于展示完整标题路径；它不是递归层级的编码，调用方不能通过拆分字符串恢复树结构。

两种模式都返回请求根的 `section_path`。`RECURSIVE` 的后代层级直接写入 Markdown 内容，调用方不需要解析或拼装 `children`。

### 2.2 `DIRECT` 模式

`DIRECT` 只读取请求中明确指定的 Section。每个 Section 的 `content` 由 Common `Section.content_spans` 按原文顺序读取，再用 `"\n\n".join(...)` 连接，不包含子 Section 正文。这个组合方式可以直接参考旧代码 `readSections`，各段内部原文不做修改。

```json
{
  "sections": [
    {
      "resource_id": "doc_llama3_spec",
      "section_id": "rsec_a1",
      "section_path": "模型架构 > 注意力机制",
      "content": "注意力机制这一节自己的正文……"
    }
  ]
}
```

### 2.3 `RECURSIVE` 模式

`RECURSIVE` 把每个请求 Section 作为一段打包阅读文本，并按 `max_depth` 读取后代。请求 Section 的相对深度记为 0，直属孩子为 1，孙节点为 2；只把深度小于等于 `max_depth` 的节点拼入 Markdown。`max_depth=0` 时只返回根 Section。`DIRECT` 模式不使用 `max_depth`。

拼接规则：

1. 每个 Section 使用它在原始 Markdown 中的真实标题级别：`section.level=1` 写 `#`，`level=2` 写 `##`，依次类推；
2. 每个 Section 先输出标题，再输出自己的直属正文；
3. 标题文本来自 Common `Section.title`，正文来自该 Section 的 `content_spans`，两者之间保留空行；
4. 达到 `max_depth` 后停止递归，不在文本中虚构未读取的内容提示；
5. 输出结果只需要根 Section 的 `resource_id`、`section_id`、完整 `section_path` 和拼接后的 `content`，不返回孩子 ID。

这相当于把 `subtree_span` 内的结构化内容打包成一段可读 Markdown；但为了支持 `max_depth`，实现不能直接切一整段 `subtree_span`，而是按 `content_spans` 逐个 Section 拼接。这样深层内容可以被准确排除，同时保留标题层级。

下面的示例使用 `max_depth=2`。请求根本身是原文的二级标题，因此输出从 `##` 开始；如果请求根是一级标题，输出就从 `#` 开始：

```json
{
  "sections": [
    {
      "resource_id": "doc_llama3_spec",
      "section_id": "rsec_a1",
      "section_path": "模型架构 > 注意力机制",
      "content": "## 注意力机制\n\n注意力机制这一节自己的正文……\n\n### MHA\n\nMHA 的正文……\n\n### GQA\n\nGQA 的正文……\n\n#### 实现细节\n\n实现细节的正文……"
    }
  ]
}
```

### 2.4 Section 处理规则

1. 所有 `section_id` 必须能定位到当前 applied Document；旧 revision ID、不存在的 ID 和无权资源使用同一种不可见错误。
2. 多个请求 Section 可以属于不同资源，按请求顺序成为 `sections` 中的结果项；递归 Markdown 内的子标题按 Common `Section.ordinal` 排序。
3. `DIRECT` 不自动读取父、子或兄弟 Section。
4. `RECURSIVE` 只沿真实 `parent_section_id` 递归，并在 `max_depth` 指定的相对深度停止，不根据标题文本猜测层级；它按每个 Section 的真实 `level` 写入 Markdown 标题，不返回嵌套 `children`。
5. 如果请求同时包含祖先和它的后代，二者仍按请求分别作为根返回。这种重复由调用方输入造成，服务不擅自删除请求项。
6. 正文不设置字符或 token 上限，不截断、不摘要、不改写。

## 3. ACL 与错误边界

Page 读取按请求的 `resource_id` 批量读取一次本地 ACL 快照。Section 读取先批量定位各 ID 的 active Document，再按资源批量读取一次 ACL 快照。上游 ACL 到 RAG 本地投影允许存在短暂传播延迟；ACL 缺失仍拒绝。读取 Document 后不再次查询同一批 ACL，因为这不能观察到尚未传播到 RAG 的上游撤销。无权访问、资源不存在、Section 不存在和旧 revision ID 对外使用统一的不可见错误，避免泄露资源是否存在。

读取能力不判断旧代码中的结构模式，只检查当前 Document 是否存在请求所需的真实 Page 或 Section。没有标题树的文档不能按 Section 读取，但只要存在 Page，仍然可以按 Page 读取。

## 4. 不属于读取能力的行为

- 不提供任意 Range 读取，也不接受或返回字符坐标。
- 图谱 Evidence 回查在图谱检索内部完成。
- 动态父块构建属于混合检索和图谱检索。
- 标题树搜索、展开和邻域查看属于标题树能力。
- 上下文预算、内容截断和摘要属于调用方。
- 本次重构不增加 Redis 整资源缓存；Mongo 当前 Document 是权威来源。

## 5. 验收标准

- 只有 Page 和 Section 两种读取方式，不存在 Range 读取接口。
- Page 结果只有 `resource_id` 和由 `page_label/content` 组成的列表。
- Section 请求只接收一批全局 `section_id`，允许一次跨资源读取；每个结果项分别返回其 `resource_id`。
- `DIRECT` Section 结果只暴露 `resource_id`、`section_id`、格式化后的完整 `section_path` 和直属 `content`。
- `RECURSIVE` Section 结果只暴露请求根的 `resource_id`、`section_id`、完整 `section_path` 和一段按真实 Markdown `level` 使用 `#/##/###/...` 拼接、深度不超过 `max_depth` 的 Markdown `content`。
- 接口不暴露 `SourceSpan`、offset 或 `content_revision`。
- 批量读取按 Section ID 定位 active Document，同一 Document 只加载一次，并保持请求根顺序和原文子节点顺序。
- `DIRECT` 不读取或合并子节；`RECURSIVE` 只按标题层级把选定深度内的 Section 正文拼成 Markdown，不截断、不摘要、不改写原文段落。
- ACL 在读取前和返回前均被核验。
