# 图谱检索

本章定义 RAG V3 的图谱检索。图谱检索不是让 Neo4j 直接返回一个“最像的子图”，而是先找到相关图元，再把图元绑定的证据 Chunk 拉回，最后对证据正文排序并取 Top-K。图元负责找路，Chunk 证据负责证明。

## 1. 两个专用 Qdrant collection

图谱检索建立两个独立 collection，分别服务 Low-Level 和 High-Level 入口。它们不是普通文档 Chunk collection。

### 1.1 `graph_node_vectors`

用途：Low-Level 实体对齐，解决“Query 具体在说哪个概念、算法、作者、数据集或资源”。一个图节点一条点记录。索引文本按 LightRAG 的实体向量索引思路，把规范名称、类别、描述和别名组合起来。

```python
def node_index_text(node: GraphNode) -> str:
    parts = [node.name, node.category]
    if node.description:
        parts.append(node.description)
    if node.aliases:
        parts.append("Aliases: " + ", ".join(node.aliases))
    return "\n".join(parts)
```

每条记录至少包含：

```text
point_id: node_vector_id
dense: embed(node_index_text(node))
payload:
  node_id
  node_type
  category
  resource_ids
  acl_projection
  metadata_projection
```

Low-Level 默认只需要 Dense ANN。节点名称、别名和类别的精确过滤由 `category` 等过滤条件和图数据库精确匹配承担。

### 1.2 `graph_edge_vectors`

用途：High-Level 关系主题检索，解决“哪些关系、演化路线、对比主题或引用链与 Query 相关”。一个关系边一条点记录。关系向量文本沿用 LightRAG 的关系 VDB 组织方式，把关键词、端点和关系描述组合成可检索文本。

```python
def edge_index_text(edge: GraphEdge, nodes: Mapping[str, GraphNode]) -> str:
    source = nodes[edge.source_node_id]
    target = nodes[edge.target_node_id]
    return "\n".join(
        (
            ", ".join(edge.keywords),
            f"{source.name} -> {target.name}",
            edge.relation_type,
            edge.description,
        )
    )
```

每条记录至少包含：

```text
point_id: edge_vector_id
dense: embed(edge_index_text(edge, nodes))
sparse: Qdrant BM25(edge_index_text(edge, nodes))
payload:
  edge_id
  source_node_id
  target_node_id
  relation_type
  keywords
  resource_ids
  acl_projection
  metadata_projection
```

High-Level 对关系文本执行 Dense + BM25 两路候选召回，在关系 collection 内按 `edge_id` 去重。节点 collection 和关系 collection 的分数不直接相加。

## 2. 请求模型和细粒度过滤

调用方支持 Query-only 和 seed-node + Query 两种入口。两种入口最后都必须经过图元过滤、Evidence 回查、粗排、局部精排和 Top-K。

```python
class GraphSearchLevel(StrEnum):
    LOW = "low"
    HIGH = "high"
    HYBRID = "hybrid"


class GraphSearchRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    query: str
    level: GraphSearchLevel = GraphSearchLevel.HYBRID
    seed_node_ids: tuple[str, ...] = ()
    resource_ids: tuple[str, ...] | None = None
    node_categories: tuple[str, ...] = ()
    relation_types: tuple[KnowledgeRelationType, ...] = ()
    direction: TraversalDirection = TraversalDirection.BOTH
    max_depth: int = Field(default=1, ge=0, le=2)
    vector_top_n: int = Field(default=20, ge=1, le=100)
    rerank_candidate_n: int = Field(default=50, ge=1, le=200)
    top_k: int = Field(default=5, ge=1, le=20)
```

`seed_node_ids` 为空时用 Qdrant 找种子；不为空时，seed 是强制起点，不会被向量检索替换。`query` 仍然必填，因为最终 Evidence 排序需要它。`rerank_candidate_n` 必须大于等于 `top_k`。

过滤字段直接对应现有 Neo4j repository 的能力：

- `resource_ids` 限定图元和 Evidence 所属资源；
- `node_categories` 限定 Low-Level 节点类别；
- `relation_types` 限定允许遍历的关系谓词，空集合表示不按谓词剪枝；
- `direction` 支持 `IN`、`OUT`、`BOTH`；
- `max_depth=0` 只读取 seed 自身关联的 Evidence，不读取邻接边；
- metadata 过滤先由垂类插件校验，再投影到 Qdrant、Neo4j 和 Mongo 查询条件。

## 3. Low、High、Hybrid 行为

### 3.1 Low-Level

Low 只在 `graph_node_vectors` 做 Dense ANN，得到有限节点种子；随后从 Neo4j 读取满足 `direction`、`relation_types` 和 `max_depth` 的邻接图，再收集节点和关系关联的 Evidence。

```text
Query -> graph_node_vectors Dense Top-N
      -> node_id 去重
      -> Neo4j 有限遍历
      -> 收集 evidence_ids
      -> Mongo Evidence -> 对应 resolver
```

Low 适合具体概念、算法细节和直接依赖问题。不做 PPR；`max_depth` 是有限遍历深度。

### 3.2 High-Level

High 只在 `graph_edge_vectors` 做关系主题召回：Dense 和 BM25 各取 Top-N，在 `edge_id` 层并集去重，再读取关系端点和满足过滤条件的邻接关系，收集 Evidence。

```text
Query -> edge_vectors Dense Top-N + BM25 Top-N
      -> edge_id 并集
      -> Neo4j 读取关系端点/邻接
      -> Mongo Evidence -> 对应 resolver
```

High 适合演化路线、方法对比和引用主题等没有单一实体起点的问题。

### 3.3 Hybrid

Hybrid 并行执行 Low 和 High：节点按 `node_id` 并集，关系按 `edge_id` 并集，随后共享 Evidence 回查和证据排序链。

```text
Low node path + High edge path
              -> 图元并集
              -> Evidence 候选并集
              -> 粗排 -> 局部精排 -> Top-K
```

Hybrid 不把两个 collection 的 ANN 分数硬加起来；统一排序发生在解析后的 Evidence 层。

## 4. 两种调用入口

### 4.1 Query-only

不传 `seed_node_ids` 时，服务按 `level` 查询专用 collection：Low 查询节点 collection，High 查询关系 collection，Hybrid 并行查询两者。每个向量分支只保留 `vector_top_n` 个图元，之后才进入 Neo4j 和 Mongo。

```text
Query
  -> Qdrant 图元候选
  -> collection 内去重
  -> metadata / ACL 过滤
  -> Neo4j 有限拓扑读取
  -> Mongo Evidence 批量回查
  -> Evidence 对应 Chunk 去重
  -> 粗排，截取 rerank_candidate_n
  -> reranker + 相关性门控
  -> Top-K Evidence
```

### 4.2 Seed-node + Query

传入 `seed_node_ids` 时，seed 是强制起点，不再调用节点 collection 替换它们。服务先校验 seed 的存在性和可读性，再按 `direction`、`relation_types`、`max_depth` 读取邻接图，最后沿用和 Query-only 完全相同的 Evidence 回查、粗排、局部精排和 Top-K 流程。

这种入口用于连续检索：普通混合检索已经披露了 Chunk 的 `node_ids`，调用方拿这些 ID 继续询问“这个节点与哪些概念存在指定关系”。

## 5. Evidence 回查

Neo4j 的节点描述、关系描述和 Qdrant 的图索引文本都不是最终证据。图元只携带稳定的 `evidence_ids`，再由与 `evidence_type` 对应的 resolver 回查真实来源：文本 Evidence 回查当前 Chunk 和 Markdown；确定性 metadata Evidence 回查当前 Document 的强类型 metadata。

```python
async def collect_evidence_blocks(
    graph_items: Sequence[GraphNode | GraphEdge],
    *,
    request: GraphSearchRequest,
    permission_scope: PermissionScope,
) -> list[ResolvedGraphEvidence]:
    evidence_ids = list(dict.fromkeys(
        evidence_id
        for item in graph_items
        for evidence_id in item.evidence_ids
    ))
    evidences = await evidence_store.get_current_readable(
        evidence_ids,
        resource_ids=request.resource_ids,
        permission_scope=permission_scope,
    )
    return await evidence_resolvers.resolve_many(
        evidences,
        permission_scope=permission_scope,
    )
```

所有 Evidence 都必须满足：目标图元存在、`content_revision` 是当前 Document 版本、资源可读。之后按类型继续校验：文本 Evidence 必须从 Markdown 回读 quote；metadata Evidence 必须从当前强类型 metadata 找到它引用的稳定记录。失败的 Evidence 不进入粗排，也不能通过图谱结果泄露。

## 6. 粗排和局部精排

图谱检索的性能关键是不能把所有关联证据全量送 reranker。LightRAG 的可复用思路是：向量库先给出有限图元候选，图元映射到 source chunk 后合并去重，再对有限文本做统一 rerank。V3 保留这个两阶段结构，排序对象扩展为统一的 `ResolvedGraphEvidence`：正文来源解析为 Chunk 证据，metadata 来源解析为确定性结构化证据。

### 6.1 粗排规则

节点 Dense 分数、关系 Dense 分数和关系 BM25 分数属于不同索引空间，不能直接相加。粗排只负责从证据池中选出最值得精排的一批：

1. 每个向量分支独立取 `vector_top_n`，保存该分支内的 rank 和原始分数。
2. 图元在自己的 ID（`node_id` 或 `edge_id`）层去重；多次命中保留最小 rank，并记录来源。
3. 图元映射到 Evidence 后按 resolver 产生的 `evidence_key` 去重；文本证据通常使用 `chunk_id`，metadata 证据使用垂类记录 ID。
4. Evidence 粗排键依次为：支持图元数量降序、最小图元 rank 升序、距离 seed 的最短跳数升序、稳定 `evidence_key` 排序。
5. 只把前 `rerank_candidate_n` 条 Evidence 送入 reranker。

粗排不是最终语义判断，也不跨 collection 比较原始向量分数。它只解决候选规模问题，保证最终精排输入是有限且有证据支撑的 Chunk。

### 6.2 Reranker 输入和结果

文本 Evidence 的 reranker 输入是标题路径和权威 Chunk 正文；metadata Evidence 由垂类 resolver 生成只陈述该结构化事实的稳定文本。两者都不能使用图谱索引文本冒充证据。

```python
def evidence_reranker_text(chunk: DocChunk) -> str:
    title = " > ".join(chunk.section_path)
    return f"{title}\n\n{chunk.raw_text}" if title else chunk.raw_text
```

将粗排后的 Evidence 转换为 Common `RankingPipeline.arank()` 的 `RankRequest`，调用现有 reranker 和 `HighLowRelevanceGate`：

```python
rank_result = await ranking_pipeline.arank(
    RankRequest(
        query=RankQuery(semantic_query=request.query),
        candidates=tuple(
            RankCandidate(
                candidate_id=evidence.evidence_key,
                text=evidence.reranker_text,
            )
            for evidence in coarse_evidences[: request.rerank_candidate_n]
        ),
        top_k=request.top_k,
        candidate_limit=request.rerank_candidate_n,
    )
)
```

`IRRELEVANT` 返回空结果；`UNCERTAIN` 原样交给上层。通过门控的文本 Chunk Evidence 可以继续动态构建父块；metadata Evidence 直接返回结构化事实及其 metadata 来源，不伪造父块。

## 7. ACL 和细粒度过滤

ACL 在四个位置执行：

```text
Qdrant collection pre-filter
  -> Neo4j 图元/邻接过滤
  -> Mongo Evidence 当前版本和权限回查
  -> 最终 Chunk 返回前 ResourceAcl.can_read
```

Qdrant ACL payload 只是提前减少不可见候选，不是权限真值。Mongo 回查必须重新使用当前 `ResourceAcl.can_read(scope)`，避免 ACL 更新与索引同步存在时序差时越权。

过滤组合规则：

- `resource_ids` 与 ACL 是 AND 关系，先限定资源再判断可读性。
- `node_categories` 只限制节点类别；关系遍历仍由 `relation_types` 单独限制。
- `relation_types` 为空表示允许所有已通过 Ontology 的关系；非空时 Neo4j 只允许列出的谓词。
- `direction=IN` 只取指向当前节点的边，`OUT` 只取从当前节点发出的边，`BOTH` 两者都取。
- `max_depth=0` 只读 seed 或向量命中图元自身证据，不读取邻接边。
- 未注册的 metadata 过滤字段直接拒绝，不能作为任意字典下推数据库。

## 8. metadata 和 Ontology 垂类扩展示例

下面只用论文引用关系 `CITES` 展示完整扩展链路。示例的目的不是让论文成为核心模型，而是证明一个垂类可以自己定义 metadata、Ontology、确定性 producer 和证据回查，同时不修改通用图谱检索。

### 8.1 论文 metadata

```python
class PaperReference(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    reference_id: str
    title: str
    doi: str | None = None
    authors: tuple[str, ...] = ()
    year: int | None = None


class PaperDocMetadata(BaseDocMetadata):
    model_config = ConfigDict(extra="forbid", frozen=True)

    doc_type: Literal["paper"] = "paper"
    title: str
    doi: str | None = None
    authors: tuple[str, ...] = ()
    institutions: tuple[str, ...] = ()
    venue: str | None = None
    year: int | None = None
    references: tuple[PaperReference, ...] = ()


class PaperChunkMetadata(BaseChunkMetadata):
    model_config = ConfigDict(extra="forbid", frozen=True)

    chunk_type: Literal["paper"] = "paper"
    section_type: Literal[
        "abstract",
        "introduction",
        "method",
        "experiment",
        "conclusion",
        "references",
        "other",
    ]
```

这个示例假设 `references` 来自论文解析器提供的结构化 metadata。`reference_id` 是该 metadata 记录内的稳定身份；它不要求引用条目同时出现在转换后的 Markdown 中。

```python
class PaperCitationMetadataEvidence(GraphEvidence):
    model_config = ConfigDict(extra="forbid", frozen=True)

    evidence_type: Literal["paper_citation_metadata"] = (
        "paper_citation_metadata"
    )
    reference_id: str
```

`PaperCitationMetadataEvidence` 证明的是“当前论文 metadata 中存在这条引用记录”。它不包含 `chunk_id`、`source_spans` 或 `quote_text`。如果另一个 producer 从正文引用段落抽取了相同关系，它可以另外生成 `TextGraphEvidence`；两种证据可以同时支持同一条 `CITES` 边。

### 8.2 只定义 `CITES` 的论文 Ontology

```python
AcademicCitationOntology = Ontology(
    domain="academic_citation",
    description="论文及其引用关系",
    entity_specs={
        "paper": EntitySpec(

    },
    relation_specs={
        "CITES": RelationSpec(
            relation_type="CITES",
            description="起点论文在参考文献中引用终点论文",
            allowed_sources=("paper",),
            allowed_targets=("paper",),

```

当前入库论文对应的节点使用 `GraphNodeKind.RESOURCE`；尚未进入知识库的被引论文使用 `EXTERNAL_RESOURCE`。Ontology 的默认类型只处理普通外部论文，producer 会显式设置当前资源节点类型。

### 8.3 从 metadata 确定性生成图事实和 Evidence

```python
def paper_node_id(*, doi: str | None, title: str) -> str:
    identity = doi.strip().lower() if doi else normalize_title(title)
    return "paper:" + sha256(identity.encode("utf-8")).hexdigest()[:20]


def citation_edge_id(source_node_id: str, target_node_id: str) -> str:
    identity = f"{source_node_id}\0CITES\0{target_node_id}"
    return "edge:" + sha256(identity.encode("utf-8")).hexdigest()[:20]


class PaperCitationProducer:
    producer_id = "paper_metadata_citation_v1"

    def produce(
        self,
        document: Document,
        ontology: Ontology,
    ) -> GraphExtractionBatch:
        metadata = document.metadata
        if not isinstance(metadata, PaperDocMetadata):
            return GraphExtractionBatch(
                producer_id=self.producer_id,
                nodes=(),
                edges=(),
                evidences=(),
            )

        source = GraphNode(
            node_id=paper_node_id(doi=metadata.doi, title=metadata.title),
            name=metadata.title,
            node_type=GraphNodeKind.RESOURCE,
            category="paper",
            extra_meta={
                "resource_id": document.resource_id,
                "doi": metadata.doi,
                "year": metadata.year,
                "venue": metadata.venue,
            },
        )
        ontology.validate_node(source)

        nodes: dict[str, GraphNode] = {source.node_id: source}
        edges: list[GraphEdge] = []
        evidences: list[PaperCitationMetadataEvidence] = []

        for reference in metadata.references:
            target = GraphNode(
                node_id=paper_node_id(
                    doi=reference.doi,
                    title=reference.title,
                ),
                name=reference.title,
                node_type=GraphNodeKind.EXTERNAL_RESOURCE,
                category="paper",
                extra_meta={
                    "doi": reference.doi,
                    "year": reference.year,
                    "authors": reference.authors,
                },
            )
            edge = GraphEdge(
                edge_id=citation_edge_id(source.node_id, target.node_id),
                source_node_id=source.node_id,
                target_node_id=target.node_id,
                relation_type="CITES",
                description=f"{metadata.title} cites {reference.title}",
                keywords=("citation", "reference"),
            )

            ontology.validate_node(target)
            ontology.validate_edge(
                edge,
                {**nodes, target.node_id: target},
            )

            evidence = PaperCitationMetadataEvidence(
                evidence_id=(
                    f"evidence:{edge.edge_id}:{reference.reference_id}"
                ),
                target_type="edge",
                target_id=edge.edge_id,
                resource_id=document.resource_id,
                content_revision=document.revision.revision_id,
                reference_id=reference.reference_id,
            )

            nodes[target.node_id] = target
            edges.append(edge)
            evidences.append(evidence)

        return GraphExtractionBatch(
            producer_id=self.producer_id,
            nodes=tuple(nodes.values()),
            edges=tuple(edges),
            evidences=tuple(evidences),
        )
```

这个 producer 完全由强类型 metadata 产生事实，因此不读取 Chunk，也不要求正文中存在引用字符串。`content_revision` 仍然必须保存：它保证 Evidence 只能回查产生它的那一版 `PaperDocMetadata`。

### 8.4 入库与检索时的证据回查

producer 的产物按下面的顺序进入通用图谱底座：

```text
PaperDocMetadata.references
  -> PaperCitationProducer
  -> AcademicCitationOntology 校验 paper -[CITES]-> paper
  -> GraphNode / GraphEdge 写 Neo4j
  -> PaperCitationMetadataEvidence 写 Mongo
  -> Node/Edge 索引文本写两个 Qdrant collection
```

论文插件同时注册 Evidence resolver：

```python
class PaperCitationEvidenceResolver:
    evidence_type = "paper_citation_metadata"

    async def resolve(
        self,
        evidence: PaperCitationMetadataEvidence,
        permission_scope: PermissionScope,
    ) -> ResolvedGraphEvidence:
        document = await document_repository.get_current_readable(
            evidence.resource_id,
            permission_scope,
        )
        if document.revision.revision_id != evidence.content_revision:
            raise StaleGraphEvidenceError(evidence.evidence_id)
        if not isinstance(document.metadata, PaperDocMetadata):
            raise InvalidGraphEvidenceError(evidence.evidence_id)

        reference = next(
            (
                item
                for item in document.metadata.references
                if item.reference_id == evidence.reference_id
            ),
            None,
        )
        if reference is None:
            raise InvalidGraphEvidenceError(evidence.evidence_id)

        return ResolvedGraphEvidence(
            evidence_key=evidence.evidence_id,
            evidence=evidence,
            reranker_text=(
                f"Paper: {document.metadata.title}\n"
                f"Cites: {reference.title}\n"
                f"DOI: {reference.doi or 'unknown'}"
            ),
            chunk=None,
        )
```

这里的 `reranker_text` 是 resolver 对已验证 metadata 事实的确定性展示，不是 LLM 生成的摘要，也不冒充论文原文。

查询引用关系时：

```python
request = GraphSearchRequest(
    query="这篇论文引用了哪些注意力机制研究？",
    seed_node_ids=(source_paper_node_id,),
    relation_types=(KnowledgeRelationType.CITES,),
    direction=TraversalDirection.OUT,
    max_depth=1,
    rerank_candidate_n=30,
    top_k=5,
)
```

执行链路是：

```text
seed paper node
  -> Neo4j 只沿 OUT CITES 取引用边
  -> edge_id 批量查询当前可读 PaperCitationMetadataEvidence
  -> resolver 回查当前 PaperDocMetadata.reference_id
  -> 再次验证 content_revision 和 ACL
  -> 确定性 metadata 事实文本进入局部 reranker
  -> Top-K metadata Evidence
```

图谱检索返回的是经过排序的 metadata Evidence 和被这些证据支撑的 `CITES` 子图。因为这个 Evidence 没有正文 Chunk，所以不构建动态父块。如果同一关系还存在 `TextGraphEvidence`，文本证据仍按 Chunk 回查、rerank 和动态装箱处理。

### 8.5 metadata 过滤如何接入

论文插件只投影实际需要查询的标量。例如首期支持按年份和 venue 过滤：

```python
class PaperMetadataFilter(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    year_from: int | None = None
    year_to: int | None = None
    venues: tuple[str, ...] = ()


def compile_paper_filter(value: PaperMetadataFilter) -> GraphStorageFilter:
    return GraphStorageFilter(
        qdrant={
            "paper_year": NumberRange(gte=value.year_from, lte=value.year_to),
            "paper_venue": MatchAny(value.venues) if value.venues else None,
        },
        neo4j={
            "year_from": value.year_from,
            "year_to": value.year_to,
            "venues": value.venues,
        },
    )
```

只有插件声明并校验过的字段才能下推。`authors`、DOI 等字段如果没有真实查询需求，就保留在垂类 metadata 或节点属性中，不提前建立过滤契约。

## 9. LightRAG 参考范围

参考 HKUDS/LightRAG commit `09f8249fdd998585fc976b86f7b2e2d5523d9db9`。复用的是方法，不是 SDK 类型或数据模型：实体向量文本由 name/description/aliases 组成；关系向量文本由端点、keywords/主题和 description 组成；local/global/hybrid 分别对应实体路径、关系路径和两路合并；图元命中后关联 source chunk，先去重合并，再做有限候选处理和 rerank。

不复用 `neo4j-graphrag` SDK、LightRAG 存储类型、LLM 输出协议、PPR、贡献聚合或其面向生成式回答的 token 截断。

## 10. 验收标准

- 只有 `graph_node_vectors` 和 `graph_edge_vectors` 两个图谱专用 Qdrant collection。
- Low 只走节点 collection；High 只走关系 collection 的 Dense+BM25；Hybrid 并行两路并集。
- Query-only 和 seed-node + Query 两种入口都支持，seed 不会被向量检索替换。
- 各向量分支独立取 Top-N，图元和 Chunk 分层去重；不直接相加跨 collection 分数。
- 粗排后只对 `rerank_candidate_n` 个当前可读 Chunk 精排，不全量调用 reranker。
- Reranker 输入只含标题和 `raw_text`，不含 keywords、contextualize prefix 或图谱索引文本。
- 使用 Common `RankingPipeline` 和相关性门控，不使用 MMR。
- `relation_types`、`direction`、`max_depth`、资源和 metadata 过滤在图遍历及 Evidence 回查中生效。
- 最终返回 Top-K Evidence；文本 Evidence 同时返回对应 Chunk 及不截断的动态父块，metadata Evidence 返回其强类型来源事实。
- 每个返回图元都有当前版本、当前 ACL 可核验的 Evidence；文本 Evidence 无法回读 quote、metadata Evidence 无法回查对应记录时，均不进入结果。
