# RAG V3 阶段性交接

更新时间：2026-09-02

本阶段实现和代码 review 已完成。以下内容是下一阶段开发的事实基线，不再记录已经处理完的 review 过程。

## 已完成

### 文档可见性、ACL 和生命周期

- Mongo 保存文档 revision、资源 active/staged 指针和本地 ACL 投影；V3 不迁移或兼容 V2 数据。
- `applied_content_revision` 是唯一线上可见性指针。stage、apply、删除清空指针均已实现；删除后的物理清理由后续异步任务完成。
- ACL 保留旧 RAG 已验证的 owner、用户显式允许/排除、群组管理员、默认群组可读和群组例外语义。RAG 缺少本地 ACL 时拒绝访问。
- 查询在候选资源集合确定后，批量取得一次 active/ACL 快照并在该请求中复用。RAG 接受上游 ACL 异步投影的短暂延迟；Qdrant、Neo4j 的 ACL 仅用于预过滤，不能单独授权返回。
- Common Section ID 会重写为由 `resource_id + content_revision + common_section_id` 计算的全局 RAG Section ID。

### 文档准备、增强、索引和混合检索

- `DocumentPreparer` 使用 Common `DocumentChunker(800, 100)` 一次性生成结构和 Chunk 事实；RAG 复用 Common 的 `Section`、`Page`、`Anchor`、`SourceSpan`、`DocumentChunk`，但自行定义 `Document`、`DocChunk`、全局 ID 和存储契约。
- `DocChunk` 保存原文、顺序、结构定位和原始坐标。`get_semantic_text()`、`get_lexical_text()` 在索引调用时计算，不持久化拼接后的索引文本。
- 文档增强使用 `instructor + Pydantic + AsyncOpenAI` 生成 `contextual_prefix` 与 `key_terms`。共享窗口固定为：不变性提示词、共享窗口、目标 Chunk；目标 Chunk 是唯一直接增强对象。
- 文档 Qdrant 建立 Dense 和 BM25 两路投影。混合检索分别取两路 Top-N、去重后将完整并集交给 Common `RankingPipeline` 局部 rerank 和相关性门控；不做 MMR，也不人为发明并集池排序。
- 命中 Chunk 是检索原子；命中后按权威 Markdown 动态装箱生成完整父块。ReadingBlock、静态父块、SourcePart、SourceRef 均未保留。
- Document apply 以文档 Dense/BM25 投影完整为前置；图谱能力不阻塞文档发布。

### 图谱事实、投影和检索

- `general` 文档不自动抽图。metadata 类型匹配且显式注册的 `GraphPlugin` 才能启用 LLM 抽取或确定性 producer；插件拥有自己的 Ontology 和 metadata filter 编译逻辑。
- LLM 节点和关系必须带能在目标 Chunk 权威 Markdown 中唯一精确回读的 quote，并保存为 `TextGraphEvidence`。
- 确定性 producer 直接从强类型 metadata 产生符合 Ontology 的图元，以 `producer_id` 标识来源；它不被强行套入 Evidence，也不要求原文 quote。
- Mongo 图谱事实是唯一权威来源；Neo4j、`graph_node_vectors`、`graph_edge_vectors` 都是可独立重建的投影。节点只建 Dense，关系建 Dense 和 BM25。
- 图谱投影、图谱构建、图谱检索与文档 apply 相互独立。`GRAPH_ENABLED=False` 时不调用图谱后端，也不影响文档索引或混合检索。
- `GraphRetriever` 已支持 Low、High、Hybrid，支持 query-only 与显式 seed node 两种入口。Low 查节点 Dense；High 查关系 Dense/BM25；Hybrid 并行三路但不融合跨 collection 原始分数。
- 图遍历按方向、关系类型、资源、metadata filter 和 `max_depth` 有界执行。候选按 LightRAG 的分支/遍历顺序进入 rerank，`candidate_limit` 限制图遍历和精排前的候选数。
- 结果区分可回读的 `ChunkGraphHit` 与确定性 `DeterministicGraphFactHit`；不向调用方返回 Qdrant 缓存正文、原始向量分数或内部 traversal 路径。

### 运行接入和模型边界

- Kafka 已是薄 transport：document-ready 依次 prepare、索引、apply；ACL 更新同步本地 ACL；资源删除先清空可见指针，再清理各类投影。
- `models.py` 只保留稳定契约：文档事实/metadata 位于 `application/document/models.py`，图谱事实/Ontology/插件位于 `application/graph/models.py`，检索调用方可见的请求/结果位于 `application/retrieval/models.py`。
- 一次调用内流转的运行时载体在首次出现的位置定义并由调用方从该位置导入：文档向量候选在 `domain/repositories/document_vectors.py`，图谱向量过滤/候选在 `domain/repositories/graph_node_vectors.py`，Neo4j 遍历来源投影在 `domain/repositories/graph_topology.py`，Mongo revision 事实读取结果在 `domain/repositories/graph_fact.py`。
- `domain/acl.py` 是唯一业务领域规则。application 负责用例编排；domain repositories 是存储端口；core 是 Mongo、Qdrant、Neo4j、Kafka 等具体适配。

## 后续开发

### P3：标题树和读取

标题树与读取只消费 active `Document`、结构事实和 ACL，不调用检索或图谱。

- 标题树提供 global outline 和 neighborhood focus；不做 hit projection。批量命中场景由调用方批量调用邻域。
- 标题树输出使用同一套符号：`{#section_id}` 表示可继续定位的节点，`[+N]` 表示该节点有 N 个直属孩子未展示；同级窗口之间真实省略的兄弟使用独占行 `⋯ [+N]`。
- neighborhood focus 返回当前 Section 的独立信息（资源 ID、Section ID、标题路径面包屑等）和缩进目录；目录不重复堆放完整结构 JSON。兄弟范围由 `sibling_steps` 控制。
- 读取只支持 Page 和 Section。Page 返回 `resource_id + [(page_label, content)]`；Section 支持 DIRECT 与带 `max_depth` 的 RECURSIVE。
- RECURSIVE 是面向连续阅读的 Markdown 文本：按 Section 在原 Markdown 中的真实标题层级拼接，不返回为导航而设计的递归 JSON，不展示 span。
- P3 落地时让读取和标题树实际消费 `ActiveDocumentSnapshotLoader`；若具体批量读取不需要它，应删除而不是保留未使用装配。

当前实现补充：P3 application 已收敛为 `application/snapshot.py`、`application/reading.py` 和 `application/outline.py` 三个顶层模块。内部请求、结果和快照载体使用 frozen dataclass；Pydantic 仅留给未来传输边界。目录中的长度单位使用 `chars`，明确表示 Python `str` 的 `len()` 结果；`demo/p3_demo.py` 使用 `demo/test.md` 的真实长文和 Common `DocumentChunker` 独立验证 Page、DIRECT/RECURSIVE、neighborhood 与 global outline。

### P4：业务入口和运维

- HTTP 查询入口已接入：`searchHybrid`、Page/Section READ、neighborhood 和 global outline 使用登录上下文、`R` 响应和 API 专属 Pydantic schema。图谱 HTTP 服务明确未进入本轮，原因和后续条件见 `HTTP服务接口.md`。
- RPC/MCP 入口只适配稳定的 application 用例；API 层负责请求反序列化、字段形态、部署上限等输入策略。
- 补齐 Kafka 重试、DLQ、日志、指标、后台清理和独立图谱投影重建任务。
- Redis 或其他缓存只在监测到明确的重复读取收益后引入；当前不缓存整篇资源。

## 后续开发规范

### 领域和数据边界

- Common 不是 RAG 契约。仅复用确有通用语义的结构、坐标、页码、anchor 和 chunker 事实；RAG 自己拥有 revision、DocChunk、索引、检索、ACL 投影和图谱契约。
- 先读生产者、消费者和真实存储，再决定模型、字段和抽象；不因旧代码、名称或预想扩展直接加状态、字段、版本、缓存或中间层。
- 稳定、跨模块、会被持久化或被调用方构造/消费的模型可以放 `models.py`。一次用例或一次仓储调用内的中间结果在首次产生的位置定义；不要为了集中管理而建立运行时模型仓库。
- 不为极低概率异常建立成套状态机、回滚协议或存储模型。跨存储投影失败允许独立重试，不能改变文档 active 指针。
- 图谱中 LLM 抽取与确定性 producer 是两条不同来源链：前者要求文本 Evidence，后者以 producer 和强类型 metadata 的确定性过程为依据。

### 校验、集合和代码组织

- API 边界校验输入 schema、格式和部署限额；application 只校验物理事实和执行安全边界，例如非空、正数量、已实现深度、外部数据是否可用。不要把 API 策略重复写进 request dataclass。
- 上游流水线已经保证的内部事实不重复 `validate`、复制或转换。仅在外部输入、第三方返回、数据库读取、安全敏感边界或高代价损坏风险处做防御。
- 服务内部默认使用 `list`、`dict`。`tuple` 只用于确实需要禁止调用方变更的公共契约或不可变值；不要在已知类型之间反复 `list()`、`tuple()` 复制。
- helper 必须承载稳定语义、复杂转换、I/O 边界或真实复用。不要把一两行机械转发、简单过滤包装成 helper、基类或“通用”模块。
- `common.py` 只放多个仓储真正共享、无业务归属的基础算子，例如 Qdrant ACL/filter 构造。只被一个文件或一个业务对象使用的实现留在该文件；不要为了复用把 node、edge、graph 等业务逻辑塞进 common。
- 新增或修改 Python 的非显然边界、算法和第三方约束使用中文注释/docstring；不要给显而易见的赋值或调用写注释。

### 存储、权限和性能

- Mongo 是 Document、DocChunk、ACL 和图谱事实的权威来源。Qdrant/Neo4j payload 只承担初检、过滤和可重建投影；返回前按 Mongo 当前 revision 和 ACL 终检。
- active revision 是内容可见性的唯一依据。旧 revision 即使物理数据尚未清理，也不得返回。
- ACL 预计算允许短暂异步传播延迟；本地 ACL 缺失必须拒绝。一次查询确定候选资源后应批量取得并复用一次本地 active/ACL 快照，避免无意义的 TOCTOU 重查。
- 所有跨资源、跨 Chunk、跨图元的读写必须批量化，禁止逐项数据库请求。大文档的 Mongo bulk write、Qdrant upsert 和 embedding 请求都必须分批；当前 embedding 批大小为 32。
- 不持久化可从权威事实重新计算的文本，例如 semantic/lexical 索引文本、动态父块正文；Qdrant 中的缓存文本不能直接作为对外正文。

### 技术路线和检索规则

- LLM 结构化抽取统一采用 `instructor + Pydantic + AsyncOpenAI`；不引入 `neo4j-graphrag` SDK 或旧 GraphRAG 输出协议。
- 文档混合检索使用两路候选并集后全量局部 rerank；图谱检索因向量命中和有界遍历的不确定性，使用 LightRAG 风格的分支/遍历顺序和 `candidate_limit` 截断后 rerank。不要混用两种候选排序目的。
- 不引入 PPR、贡献聚合、MMR、全图扫描或图缓存。图谱检索不负责重新构建图谱或修复投影。
- 缓存、垂类插件和新的 Ontology 都必须有明确调用方和可审计收益后再实现；不能为了未来可能性劫持当前通用流程。
