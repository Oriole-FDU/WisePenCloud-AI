# 混合检索

本章定义 RAG V3 的混合检索能力。它不是 MCP 工具说明，也不把上层工具的参数形状下沉为 RAG 契约。

混合检索同时承担两件事：

1. 找到传统 RAG 要交付的命中子块，并在返回前按结构和坐标构建更完整的动态父块。
2. 随命中结果披露这些 Chunk 已经抽取出的 `node_id`，供后续知识图谱检索选择 seed node。

## 1. 检索对象和结果边界

`DocChunk` 是召回和精排的最小对象。它拥有 `chunk_id`、`resource_id`、`content_revision`、`section_id`、`section_path`、`raw_text`、`source_spans`、`contextual_prefix`、`key_terms` 以及图谱抽取产生的 `extracted_node_ids`。

`extracted_node_ids` 是从该 Chunk 抽取、校验并已写入图谱的实体节点 ID，不是 Chunk ID。它只表达 Chunk 与实体节点的证据关联，不代表本次查询已经执行图谱推理。后续图谱检索可以直接使用这些 ID 作为 seed node。

`section_id` 是 RAG 入库时根据 `resource_id + content_revision + Common section_id` 重写后的全局 ID，不是 Common 的内容内局部 ID。调用方可以把多个命中中的 Section ID 去重后，一次传给标题树邻域或 Section 读取，不需要先按资源拆分调用。

```python
class ChunkHit(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    chunk_id: str
    resource_id: str
    content_revision: str
    section_id: str | None
    section_path: tuple[str, ...]
    rerank_score: float
    # 从该 Chunk 抽取并已入图的实体节点 ID。
    node_ids: tuple[str, ...]


class DynamicParent(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    parent_id: str
    resource_id: str
    content_revision: str
    section_ids: tuple[str, ...]
    text: str
    source_spans: tuple[SourceSpan, ...]
    matched_chunk_ids: tuple[str, ...]
    score: float


class HybridRetrievalResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    hits: tuple[ChunkHit, ...]
    parents: tuple[DynamicParent, ...]
    relevance_decision: RankDecision
```

`HybridQuery.lexical_query` 允许调用方提供更适合 BM25 的关键词；未提供或传空字符串时，构造时直接回填 `semantic_query`。因此后续 Dense、BM25 和 ranking 请求都只读取 `query.lexical_query`，不额外暴露 `resolved_lexical_query` 一类中间字段。

`hits` 用于审计真实命中的小块，其中每个 `ChunkHit.node_ids` 披露该 Chunk 关联的已入图实体节点；`parents` 用于传统 RAG 阅读。调用方需要图谱 seed 时，从准备继续探索的具体 Hit 中选择 `node_ids`，而不是使用一个脱离 Chunk 证据来源的全局并集。父块正文和坐标都来自当前 `Document.raw_content`，不是 Qdrant payload 中的缓存文本。

## 1.1 `DocChunk` 如何变成 `ChunkHit`

Qdrant 返回的只是候选引用和初检信号，例如 `chunk_id`、Dense/BM25 rank、资源/版本和预过滤 payload；它本身不是 `ChunkHit`。`ChunkHit` 在以下步骤构造：

```text
Qdrant Dense/BM25 候选
  -> 按 chunk_id 并集去重
  -> Mongo 批量回查当前版本的 DocChunk
  -> 复核 source_spans、raw_text 和 ResourceAcl
  -> reranker 选出最终命中并得到 rerank_score
  -> 用最终命中的 DocChunk + 分数构造 ChunkHit
```

实际构造逻辑如下：

```python
def to_chunk_hit(
    chunk: DocChunk,
    *,
    rerank_score: float,
) -> ChunkHit:
    return ChunkHit(
        chunk_id=chunk.chunk_id,
        resource_id=chunk.resource_id,
        content_revision=chunk.content_revision,
        section_id=chunk.section_id,
        section_path=chunk.section_path,
        rerank_score=rerank_score,
        node_ids=chunk.extracted_node_ids,
    )
```

因此，`node_ids` 的挂载点是“最终命中投影”这一步，而不是向量召回或 reranker 输入构造这一步。它来自当前 Mongo `DocChunk` 的 `extracted_node_ids`，并随该 Chunk 的 `chunk_id` 一起返回，保证图谱 seed 能追溯到具体命中小块。

Qdrant payload 可以带 `extracted_node_ids` 以便候选阶段快速披露或过滤，但回查后的 Mongo 值是最终依据。若 payload 与 Mongo 不一致，按 Mongo 当前值返回，并记录索引陈旧；不能让过期 payload 把不存在或未入图的节点暴露给调用方。

## 2. 索引文本

Qdrant 的 Dense 和 BM25 都以 `DocChunk` 的方法生成索引输入，不以 `raw_text` 单独入库。

```python
class DocChunk(BaseModel):
    # 省略身份、坐标和增强字段

    def get_semantic_text(self) -> str:
        """Dense 输入：标题路径 + contextualize 前缀 + 正文。"""
        parts: list[str] = []
        if self.section_path:
            parts.append(" > ".join(self.section_path))
        if self.contextual_prefix.strip():
            parts.append(self.contextual_prefix.strip())
        parts.append(self.raw_text)
        return "\n\n".join(parts)

    def get_lexical_text(self) -> str:
        """BM25 输入：标题路径 + 关键词 + 正文。"""
        parts: list[str] = []
        if self.section_path:
            parts.append(" ".join(self.section_path))
        if self.key_terms:
            parts.append(" ".join(self.key_terms))
        parts.append(self.raw_text)
        return " ".join(parts)
```

规则固定如下：

- Dense 输入包含 `section_path`、`contextual_prefix`、`raw_text`；不包含 `key_terms`。
- BM25 输入包含 `section_path`、`key_terms`、`raw_text`；不包含 `contextual_prefix`。
- 进入 reranker 的文本不是上述索引文本。reranker 输入只允许“标题路径（建议置于开头）+ `raw_text`”；不得带 `contextual_prefix` 或关键词，否则增强提示会污染相关性判断。
- `semantic_index_text`、`lexical_index_text` 都不是持久化字段；重建索引时重新调用方法即可。

## 3. Qdrant 两路入库

每个 `DocChunk` 在同一个 Qdrant collection 写入两个向量：一个 Dense 向量和一个 BM25 稀疏向量。两路共享同一个 `chunk_id`、`content_revision` 和 ACL payload。

```text
DocChunk.get_semantic_text() -> embedding model -> dense vector
DocChunk.get_lexical_text()  -> Qdrant BM25  -> sparse vector
```

Payload 只保存候选定位和前置过滤需要的标量：

- `chunk_id`、`resource_id`、`content_revision`、`section_id`、`section_path`；
- `extracted_node_ids`，用于把命中 Chunk 关联到后续图谱 seed；
- ACL 投影字段；
- 垂类插件明确声明、且确实用于过滤的 metadata 标量。

不把父块、`contextual_prefix`、关键词拼接文本或大段正文升级成 Qdrant 契约。候选返回后必须回查 Mongo 当前 `Document` 和 `DocChunk`，确认版本、坐标、原文和 ACL。

## 4. 两路召回和并集池

一次查询分别执行 Dense 和 BM25，各自取独立的 Top-N。两路不能使用 Qdrant Fusion/RRF，也不能在初检阶段把两个分数相加。

```python
async def collect_candidates(
    query: HybridQuery,
    permission_scope: PermissionScope,
    *,
    top_n: int,
) -> list[CandidateRef]:
    qdrant_filter = acl_filter(permission_scope)
    dense, lexical = await asyncio.gather(
        qdrant.search_dense(
            vector=embed(query.semantic_query),
            query_filter=qdrant_filter,
            limit=top_n,
        ),
        qdrant.search_bm25(
            text=query.lexical_query or query.semantic_query,
            query_filter=qdrant_filter,
            limit=top_n,
        ),
    )

    by_chunk_id: dict[str, CandidateRef] = {}
    for item in (*dense, *lexical):
        current = by_chunk_id.get(item.chunk_id)
        if current is None:
            by_chunk_id[item.chunk_id] = item
        else:
            by_chunk_id[item.chunk_id] = current.merge_signal(item)
    return list(by_chunk_id.values())
```

并集池只按 `chunk_id` 去重，并保留 Dense/BM25 各自的来源信号供审计；不按最小 rank、RRF 或其他人为规则重新排序，也不把两个量纲不同的初检分数混成最终分数。去重后的全部候选直接交给 Common `RankingPipeline`。`top_n` 是每一路的候选数，`top_k` 是最终允许进入父块装箱的命中数，两者不能混用。

## 5. ACL 过滤和回查

ACL 在 Qdrant 召回前作为预过滤；进入 application 后按资源批量读取一次本地 ACL，形成本次请求的权限快照。

```text
请求 PermissionScope
        │
        ▼
Qdrant Dense/BM25 pre-filter
        │
        ▼
按 chunk_id 并集
        │
        ▼
Mongo 回查当前 Document、DocChunk，并使用已建立的 ResourceAcl 快照
        │
        ├─ 资源不存在、版本不是当前版本、坐标不匹配 -> 丢弃候选
        └─ ACL.can_read(scope) == False -> 丢弃候选
        │
        ▼
进入 reranker
```

Qdrant ACL filter 必须与 `ResourceAcl.can_read()` 同语义：owner 和显式用户授权、managed group 放行、joined group 默认权限和成员例外、资源级排除优先阻断普通群组授权。不能因为 Qdrant pre-filter 已经做过一次就省略 Mongo ACL 快照；ACL 事件和本地投影更新允许存在短暂时序差。查询过程中不重复读取同一批本地 ACL，因为重复读取无法观察到尚未传播到 RAG 的上游变更。

## 6. Reranker 和 Common 相关性门控

精排输入只使用标题和权威 Chunk 正文：

```python
def reranker_text(chunk: DocChunk) -> str:
    title = " > ".join(chunk.section_path)
    return f"{title}\n\n{chunk.raw_text}" if title else chunk.raw_text
```

将回查后的候选转换为 Common ranking 的 `RankRequest`，调用现有 reranker，然后调用 `HighLowRelevanceGate`。门控结果中的 `RankDecision`、最高相关性分数和排序后的候选直接作为检索结果依据。

```python
rank_result = await ranking_pipeline.arank(
    RankRequest(
        query=RankQuery(semantic_query=query.semantic_query),
        candidates=tuple(
            RankCandidate(
                candidate_id=chunk.chunk_id,
                text=reranker_text(chunk),
            )
            for chunk in readable_chunks
        ),
        top_k=query.top_k,
        candidate_limit=len(readable_chunks),
    )
)
```

V3 的 ranking pipeline 必须配置 reranker 和 `HighLowRelevanceGate`，不配置 MMR/diversifier。门控发生在最终命中选择之前；如果结果为 `IRRELEVANT`，返回空命中和对应的 `RankDecision`，不能靠动态装箱把低相关候选“救回来”。`UNCERTAIN` 是否交给上层追问或继续工作流，由上层策略决定，RAG 不伪造答案。

## 7. 动态父块构建

旧 `ReadingBlock` 废除。命中 Chunk 经过精排后，在内存中动态构建父块；父块没有独立持久化身份，也没有静态父子映射表。

输入是最终 `ChunkHit` 及其 `section_id`、`chunk_index`、`source_spans`，输出是完整连续的 `DynamicParent`。

```text
1. 按 `(resource_id, content_revision, section_id)` 聚合最终命中 Chunk。
2. 同一 Section 内相邻、或只隔一个未命中 Chunk 的命中合并为连通组；每组向前、向后各扩展一个同 Section 邻居。
3. Section 长度不超过 4000 字符时，直接返回完整 `Section.own_span`。
4. 否则，Section 不超过 8000 字符、只有一个连通组且其覆盖率至少 80% 时，直接返回完整 `Section.own_span`。
5. 其余情况返回每个完整连通组。无标题文档只有本条路径，作用域是完整 Document。
6. 所有路径均从 `Document.raw_content` 按精确 `SourceSpan` 切出正文，继承对应命中最高 rerank score 并记录 `matched_chunk_ids`。
```

4000、8000 和 80% 只决定“整 Section”还是“局部连通父块”，不是输出预算。Chat Service 原来的第三条路径会在局部范围超过 6000 字符时返回 range 读取建议；V3 不提供这个指针，因此这里始终直接返回完整连通区间。

“不截断”是硬约束：

- 不设 6000 字符父块上限，也不为了满足模型窗口静默裁剪；
- 一个 Section 过长时，按结构边界和命中区间返回多个完整 `DynamicParent`，每个父块仍然是完整的连续坐标区间；
- 上层如果需要上下文预算，由上层显式处理，不能修改 RAG 返回的 `text` 或 `source_spans`；
- 父块正文必须从当前 `Document.raw_content` 重建，不能使用旧 `ReadingBlock.raw_text` 或 Qdrant payload 正文。

## 8. 返回实体节点 ID

实体节点 ID 随各自的 `ChunkHit` 返回，不在结果顶层再次聚合：

```python
hit = ChunkHit(
    chunk_id=chunk.chunk_id,
    resource_id=chunk.resource_id,
    content_revision=chunk.content_revision,
    section_id=chunk.section_id,
    section_path=chunk.section_path,
    rerank_score=ranked.score,
    node_ids=tuple(dict.fromkeys(chunk.extracted_node_ids)),
)
```

只披露最终通过 ACL、当前版本回查和相关性门控的命中 Chunk 所关联的实体节点 ID。被 Dense/BM25 初检召回但后来被淘汰的 Chunk，其实体节点 ID 不得泄露。保留 Chunk 到节点的对应关系，也让调用方知道每个 seed 是由哪段正文命中的。

## 9. 端到端流程

```text
HybridQuery + PermissionScope
          │
          ▼
ACL/metadata 编译为 Qdrant filter
          │
          ├── Dense Top-N: get_semantic_text()
          └── BM25 Top-N:  get_lexical_text()
                    │
                    ▼
              chunk_id 并集池
                    │
                    ▼
      Mongo 当前 Document/DocChunk/ACL 回查
                    │
                    ▼
     标题 + raw_text -> Common reranker
                    │
                    ▼
             HighLowRelevanceGate
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
      无有效命中             有效 ChunkHit
      空结果+decision          │
                              ▼
                 动态父块完整装箱（不截断）
                              │
                              ▼
             返回 hits（含各自 node_ids）+ parents
```

## 10. 验收标准

- Dense 和 BM25 各自独立取 Top-N，按 `chunk_id` 做并集后全量交给 reranker；不存在额外粗排、Qdrant Fusion/RRF 或 MMR。
- Dense 只使用标题、`contextual_prefix`、正文；BM25 只使用标题、关键词、正文。
- Reranker 输入不包含 prefix 和关键词，标题可以放在正文开头。
- 所有候选先做 Qdrant ACL pre-filter，再做 Mongo 当前版本和 `ResourceAcl.can_read()` 回查。
- 最终结果只在各个 `ChunkHit` 中披露该 Chunk 对应的已入图实体节点 ID，不返回脱离 Chunk 来源的顶层并集。
- `IRRELEVANT` 不返回命中；`UNCERTAIN` 保留 Common 的门控判定，不在 RAG 内部擅自改写。
- 不再创建或读取静态 `ReadingBlock`；父块在查询时动态构建。
- 动态父块不做字符/token 截断，正文和 `SourceSpan` 能从当前 `Document.raw_content` 精确复核。
- 父块构建不会跨越不可跨越的 Section 结构边界，多个命中区间不会因为预算被强行拼接或裁短。
