# Notes 后续能力规划

本文档记录 `notes` 工具体系后续计划能力和边界。本轮只做规划埋点，不实现运行代码。

## 计划能力

### 笔记 to PPT

预计实现从 Markdown 笔记生成 PPT 的能力。第一阶段只支持默认学术风格的 `md -> ppt`，不做通用 PPT 生成器。

默认能力边界：

1. 输入以结构化 Markdown 笔记为主。
2. 输出为默认学术汇报风格 PPT。
3. 重点支持标题层级、段落、列表、公式、图片引用、表格和引用信息的稳定转换。
4. 默认模板由系统内置，不暴露复杂模板 DSL。
5. 不支持自由设计、营销风、商业路演风、品牌视觉全套定制等通用 PPT 生成需求。

后续只有出现明确模板需求时，再增加模板能力。模板能力应作为增量功能设计，而不是把第一版做成通用 PPT 生成器。

### AI 笔记编辑

预计实现 AI 辅助笔记编辑能力，用于对已有笔记做结构化修改。

可能覆盖：

1. 调整标题层级和章节结构。
2. 合并重复内容。
3. 补全过渡段和摘要。
4. 将散乱内容整理为学术笔记格式。
5. 对公式、术语、引用上下文做局部修正。

该能力应优先服务“编辑已有笔记”，而不是从零生成任意长文。

### AI 全自动化实时润色

预计实现笔记编辑过程中的实时润色能力。

可能覆盖：

1. 语句顺滑化。
2. 学术表达规范化。
3. 中英文混排优化。
4. 术语一致性修正。
5. 局部段落压缩或展开。

该能力应保持低侵入。实时润色不应擅自改变笔记事实、公式含义或引用关系。

## 明确不做

第一阶段不做：

1. 通用 PPT 生成器。
2. 任意风格模板市场。
3. 复杂动画、转场和交互组件。
4. 自动编造图片、图表或引用。
5. 大规模文档排版系统。

## 后续实现提示

`notes_to_ppt` 已有空骨架，后续实现时建议保持以下边界：

1. tool 层只暴露输入、输出格式和必要参数。
2. service 层负责 Markdown 解析、结构规划和渲染编排。
3. domain 层表达笔记结构、slide outline、学术模板约束。
4. implementations 层承载具体 PPT 渲染实现。
5. 如果后续接入模板，模板应是受控配置，不应让调用方提交任意执行逻辑。

第一版目标是稳定、可控、默认学术风，而不是覆盖所有 PPT 设计场景。
