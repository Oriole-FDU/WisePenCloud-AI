RAG 链路数据模型与流转图

这份图只描述当前 RAG 业务语义：资源如何变成线上索引，查询如何跨 Dense / BM25 / Keyword 三路召回，候选如何融合、父块聚合、重排、MMR 选择，最后进入可回答上下文。

Overview

一条 RAG 链路，分成“索引发布”和“线上检索”两条主干

索引侧负责把用户资源变成多版本、可过滤的物理索引；检索侧只读取已发布 Manifest 指向的 index_version，不读取未发布影子版本。

索引发布链路

ResourceServiceRagIndexWorkerManifest last

资源写入后生成 VersionSnapshot 和 RagIndexMessage。Worker 消费消息，校验资源事实版本仍有效，完成 Mongo / Qdrant / Elasticsearch 写入后，最后发布 RagIndexManifest。

Indexing 1/4

资源写入：RagResource 是 RAG 的事实源

资源服务不直接写索引。它保存资源事实，计算索引版本快照，并发布异步索引消息。

输入事实：RagResource

RagResource 表示 note / document 的当前业务事实。version 用于淘汰过期 indexing message，is_deleted 会使线上 Manifest 删除。

resource_iduser_idresource_kindcontentversionis_deleted

版本计算：VersionSnapshot

material_hash 由 resource_kind、resource_id、content_hash、display_name 计算；pipeline_version 由分块、索引文本、embedding、context 配置计算；index_version 由 user_id、resource_id、material_hash、pipeline_version 共同决定。

dataclass关键字段语义强关联
RagResourcedisplay_namenote 用 title，document 用 document_name；进入 material_hash、索引文本和 evidence 展示。影响 VersionSnapshot.material_hash
VersionSnapshotindex_version索引代次，不直接包含 resource.version。贯穿 Mongo / Qdrant / Elasticsearch / Manifest / RetrievalScope
RagIndexMessageexpected_versionWorker 用它判断消息是否被后续资源更新淘汰。必须等于当前 RagResource.version
Indexing 2/4

父子分块：RetrieveChunk 用于阅读，SearchChunk 用于召回

RAG 明确区分阅读单位和检索单位。SearchChunk 只能在单个 RetrieveChunk 内继续切分，不允许跨父块。

RagResource.content

资源完整原文，不能被摘要替代。

→

RetrieveChunk

父块，阅读和 citation 的最终主证据来源。

→

SearchChunk

子块，写入 Qdrant / Elasticsearch，用于多通道召回。

RetrieveChunk 字段

chunk_id/resource_id/resource_kind/chunk_index/text/content_hash

chunk_id 包含资源类型、resource_id、retrieve 序号和 content_hash 前缀。

SearchChunk 字段

chunk_id/parent_chunk_id/parent_chunk_index/chunk_index/text/content_hash

parent_chunk_id 是回连父块、neighbor、evidence 组装的核心外键。

Indexing 3/4

Context Indexing 与双索引文本

Context Indexing 永远启用。它给 SearchChunk 生成检索上下文，增强语义召回；但 keyword_text 必须保持原文，服务 exact 检索。

SearchChunkContext

chunk_id + context_text

由 context client 基于 resource、parent_chunk、search_chunk 生成。缓存键包含模型版本、prompt 版本和 context_input_hash。

semantic_indexing_text

组合 display_name、resource_kind、retrieval_context、chunk text。

用于 dense embedding 与 Qdrant BM25 document。

keyword_text

严格等于 SearchChunk 原文。

用于 Elasticsearch keyword exact，不能混入 LLM context_text。

强边界：Context Indexing 是索引增强，不是 evidence 原文。最终回答仍要回到 RetrieveChunk 原文、matched search text 与 neighbor texts。
Indexing 4/4

三处物理写入全部成功后，Manifest 才发布

Manifest 是线上检索指针。它不表达构建过程状态，只表达当前已发布的 index_version。

Mongo Chunk Store

保存 RetrieveChunk、SearchChunk、retrieval_context、semantic_indexing_text、keyword_text。

Qdrant

SearchChunk point：dense vector + BM25 document + payload 强过滤字段。

Elasticsearch

keyword_text、display_name、heading_path，服务 keyword_exact 通道。

RagIndexManifest

user_id/resource_kind/resource_id/resource_version/material_hash/pipeline_version/current_index_version

检索侧只读取 current_index_version。Manifest 发布前，旧版本仍然服务线上检索。

Retrieval 1/5

rag_search 工具入口：从模型参数变成 RagRetrievalQuery

工具层注入 user_id，验证 query、mode、resource_kinds 和 query variants，再套用 mode 默认水位。

ModeRetrievalDefaults

normal / semantic / exact 影响 top_k、fusion_top_k、rerank_top_n、final_top_k、neighbor_before、neighbor_after、mmr_lambda 和 query variant 上限。

RagRetrievalQuery

user_id/query/semantic_queries/keyword_queries/mode/resource_kinds/top_k/fusion_top_k/rerank_top_n/final_top_k/neighbor_before/neighbor_after/mmr_lambda

边界：RAG 查询只面向用户已索引 note/document。当前事实、公开网页、新闻、价格、法规应走 web_search。
Retrieval 2/5

Manifest Resolver 生成线上检索范围

检索不会扫全库。它先读取用户已发布 Manifest，转换为 RagIndexScope，所有下游检索都强绑定 scope。

RagIndexScope

user_id/resource_kind/resource_id/index_version

每条 scope 对应一个已发布 Manifest。没有 scope 时直接返回空结果，避免 Qdrant / ES 无过滤扫描。

多租户与版本隔离

Qdrant payload filter 和 Elasticsearch bool filter 都必须包含 user_id、resource_kind、resource_id、index_version。

Retrieval 3/5

三路召回：Dense Semantic、Sparse Lexical、Keyword Exact

RagRetrievalOrchestrator 只负责并发召回，不做融合、不组装 evidence、不 rerank。

Dense Semantic

Qdrant dense vector。query 先走 embedding cache，未命中再调用 embedding client。

Sparse Lexical

Qdrant BM25 document。使用 semantic_indexing_text 做词法召回。

Keyword Exact

Elasticsearch keyword_text / display_name / heading_path，多字段 boost。

dataclass字段语义
RagRetrievedCandidatechannel/score/chunk_id/parent_chunk_id/matched_query子块级召回候选，不携带父块原文。
ChannelRetrievalResultchannel/candidates单个召回通道返回的一组 SearchChunk 级命中。
Retrieval 4/5

RRF 融合后，必须从 SearchChunk 聚合回 RetrieveChunk 父块

多通道融合仍然是子块级结果。最终 evidence 必须是父块级，才能保持完整阅读上下文和 citation 稳定性。

RagFusedCandidate

candidate/rrf_score/rank/sources

候选 key 由 user_id、resource_kind、resource_id、index_version、chunk_id 构成。

ParentCandidate

chunk_id 是父块 ID；best_child_hit 保留最强子块命中；matched_channels 和 matched_queries 稳定去重。

强关联：SearchChunk.parent_chunk_id → ParentCandidate.chunk_id → Mongo 读取 RetrieveChunk → 最终 evidence 的 parent_chunk_id。
Retrieval 5/5

水合、重排、MMR、多样性选择

EvidenceAssembler 读取 Mongo 补全原文和相邻父块，构造 rerank_text 和 mmr_text。ZeroEntropy 负责相关性重排，MMR 控制同资源/同父块霸榜。

RagHydratedCandidate

parent_candidate + search_record + parent_chunk + neighbor_chunks + rerank_text + mmr_text + group_key。

RerankableDocument

id/text 进入 ZeroEntropy。输出 RerankedDocument(id/score/rank)。

MMR

使用 relevance_score、similarity_text、group_key，最终选出 final_top_k。

最终模型关键字段职责
RagEvidencetext/search_text/retrieval_context/neighbor_texts回答可见证据，父块原文为主，search text 解释命中点，neighbor 补上下文。
SufficiencyResultsufficient/reason检索可用性边界，不等于最终答案完整性。
Output

Context Assembler 产出最终 evidence pack

最终输出不是候选列表，而是按资源分组、按父块顺序拼接后的 assembled context，并携带 Answerability 策略。

RagAssembledContext

text/included_evidence_ids/skipped_evidence_count

按资源分组，组内按 parent_chunk_index 排序；断层用 [...] 表示；总长度受 MAX_CONTEXT_CHARS 控制。

Answerability

如果 sufficient=false，工具输出会要求模型不要假装知识库支持该结论。NO_RESULTS、LOW_SCORE、EXACT_MODE_NO_KEYWORD_HIT 分别给出不同拒答策略。

使用规则：Assistant 必须只基于 assembled context 回答；RAG evidence 不覆盖 web_search 的当前事实能力。

Strong Links

必须保持稳定的强关联关系

这些关联一旦断裂，会造成越权检索、读错版本、候选无法水合、citation 不稳定或回答无法追溯。

多租户隔离

user_id 必须进入 index_version 计算、Mongo/Qdrant/ES payload/filter 和 retrieval query。

版本隔离

Manifest.current_index_version 是线上唯一读指针。检索侧不能扫描未发布 index_version。

父子块回连

SearchChunk.parent_chunk_id 必须指向同资源同版本的 RetrieveChunk.chunk_id。

原文边界

keyword_text 和最终 RagEvidence.text 必须来自原文，不应被 LLM context_text 替换。

发布顺序

Mongo chunks、Qdrant points、Elasticsearch docs 全部成功后才能发布 Manifest；删除资源时先删 Manifest，让线上立即退出检索，物理索引交给 GC。
