# DOCX 解析器

本目录实现 DOCX 到 Markdown 的结构化解析。DOCX 本质上是一个 ZIP 包，解析器直接读取其中的 OOXML 文件，将正文中的段落、表格和内联内容按原始顺序转换为 Markdown。

## 解析入口

上层统一通过 `parse_docx` 调用：

```python
from chat.application.utils.document_parse.parse_docx import parse_docx

markdown = parse_docx(
    "example.docx",
    image_path="output/images",
)
```

`image_path` 用于保存 DOCX 内嵌图片。未提供该参数时，图片仍会生成 Markdown 图片引用，但不会被解压到外部目录。

## 解析内容

### 正文结构

- 按 `word/document.xml` 中正文节点的原始顺序解析段落、表格和节属性。
- 解析结构化文档标签（内容控件）内部的正文内容，不把内容控件本身当作独立 block。
- 识别 Word 标题样式、标题继承关系和大纲级别，转换为 Markdown 的一至六级标题。
- 识别段落编号和项目符号，支持十进制、补零十进制、字母和罗马数字等常见编号格式。
- 保留列表层级，并在进入上层列表时重置更深层级的计数。

### 内联内容

- 普通文本，包括删除文本节点中的文字。
- 制表符、普通换行和分页符。
- 直接超链接、`HYPERLINK` 域链接以及文档内部锚点。
- 内嵌图片、外部图片链接和图片替代文本。替代文本优先使用 Word 图片描述或标题，没有时使用图片文件名。
- DrawingML/VML 文本框中的文字，以引用块形式保留。
- Word 公式（OMML）的常见结构，包括分数、根式、上下标、积分/求和、函数、括号和矩阵，并转换为行内 LaTeX。
- 脚注和尾注引用；对应的定义统一追加到正文末尾的 `## Notes` 区域。
- Word 批注引用会保留为 `<comment-ref id=... />` 标记。当前解析器不读取批注正文。

### 表格

- 没有合并单元格或嵌套表格的普通表格转换为 Markdown 管道表。
- 普通表格中的反斜杠、管道符和换行会进行 Markdown 兼容处理。
- 包含横向合并、纵向合并或嵌套表格的复杂表格转换为 HTML。
- 复杂表格保留 `colspan`、`rowspan` 和嵌套表格结构，避免用 Markdown 表格丢失布局语义。

## 保留的语义信息

解析结果重点保留以下信息，便于后续检索、分块和模型阅读：

| DOCX 语义 | Markdown 表达 |
| --- | --- |
| 段落和表格顺序 | Markdown block 顺序 |
| 标题层级 | `#` 至 `######` |
| 有序/无序列表及层级 | 编号前缀或 `-`，层级使用缩进 |
| 普通表格 | Markdown 管道表 |
| 合并或嵌套表格 | HTML 表格及合并属性 |
| 超链接 | `[文本](地址)` |
| 内部锚点 | `[文本](#锚点)` |
| 图片 | `![替代文本](路径)` |
| 公式 | `$...$` 包裹的 LaTeX |
| 分页 | `<!-- page N -->` 页面标记 |
| 脚注/尾注 | 正文引用和末尾定义 |
| 文本框 | Markdown 引用块 |

页面标记根据显式分页符、Word 保存的排版分页标记以及节边界生成。它用于保留页级定位信息，不代表重新执行 Word 的排版引擎。

## 不保留的内容

该解析器是语义转换器，不是 Word 页面渲染器，因此不会完整保留：

- 字体、字号、颜色、粗体/斜体、下划线等字符级视觉样式。
- 页边距、行距、分页布局、页眉页脚和浮动对象的精确位置。
- Word 批注正文、修订记录的作者和变更属性。
- 复杂图形、SmartArt、图表等对象的完整可编辑结构。

图片二进制数据只有在传入 `image_path` 时才会被解压保存；公式、表格和文本框会尽量保留其内容与结构，但不保证与 Word 中的视觉效果完全一致。

## 实现位置

DOCX 解析实现集中在 `converter.py`。该文件读取 DOCX 包，并在同一处处理正文 block 顺序、分页、样式标题、编号、内联文本、链接、图片、公式、表格以及脚注/尾注输出。
