# 图谱检索

图谱检索先用图元找到相关路径，再把候选收敛成可排序的返回内容。图谱事实有两种来源，二者不强行使用同一套 Evidence 抽象：

- **LLM 抽取**：模型可能产生幻觉，节点和关系必须关联可回读的 `TextGraphEvidence`；检索后回到当前 Chunk 和 Markdown 校验。
- **确定性 producer**：输入是已校验的强类型 metadata 或其他确定性记录，producer 本身就是从来源事实到图元的严格转换；图元直接参与检索，不创建 metadata Evidence、Evidence 类型或 resolver。

两条路径在最终候选排序阶段汇合，并统一返回模型可读的 `GraphSearchHit`。LLM 路径的 `text` 是经 Evidence 验证的完整 Chunk 正文；确定性路径的 `text` 是来源投影 `get_fact_text()` 生成的事实文本。

## 1. 两个专用 Qdrant collection

### 1.1 `graph_node_vectors`

节点只建立 Dense 索引：

```python
def node_index_text(node: GraphNode) -> str:
    parts = [node.name, *node.aliases, node.description]
    return "\n".join(part for part in parts if part)
```

节点检索回答的是“用户在说哪个实体”。实体名称通常短、别名有限，Dense 更适合处理别名、缩写和语义近似。对节点再建 BM25 很容易让精确名称重复成为主导信号，但不会明显提升关系主题检索能力。

payload 只放过滤和回查需要的字段：`node_id`、类别、资源/revision 归属、ACL 预过滤和已注册的 metadata 投影。

### 1.2 `graph_edge_vectors`

关系建立 Dense 和 BM25 两路索引：

```python
def edge_index_text(edge: GraphEdge, nodes: Mapping[str, GraphNode]) -> str:
    source = nodes[edge.source_node_id]
    target = nodes[edge.target_node_id]
    parts = [
        f"{source.name} -> {edge.relation_type} -> {target.name}",
        " ".join(edge.keywords),
        edge.description,
    ]
    return "\n".join(part for part in parts if part)
```

关系既有自然语言语义，也有明确谓词、端点名称和关键词。Dense 负责语义近似，BM25 负责 `CITES`、`AUTHORED_BY`、方法名等精确词命中，两路互补。

payload 放 `edge_id`、端点、关系类型、资源/revision 归属、ACL 预过滤和已注册的 metadata 投影。Dense 与 BM25 各取 Top-N，在 `edge_id` 层并集去重，不直接相加分数。

## 2. 请求和过滤

调用方支持 Query-only 和 seed-node + Query 两种入口：

```python
class GraphSearchLevel(StrEnum):
    LOW = "low"
    HIGH = "high"
    HYBRID = "hybrid"


@dataclass(frozen=True, slots=True)
class GraphSearchRequest:
    query: str
    level: GraphSearchLevel = GraphSearchLevel.HYBRID
    seed_node_ids: list[str] = field(default_factory=list)
    resource_ids: list[str] | None = None
    node_categories: list[str] = field(default_factory=list)
    relation_types: list[str] = field(default_factory=list)
    direction: TraversalDirection = TraversalDirection.BOTH
    max_depth: int = 1  # 0..2
    vector_top_n: int = 20  # 每个向量分支的召回上限
    candidate_limit: int = 50  # 并集池和图遍历最多送入精排多少条
    top_k: int = 5  # 1..20
    plugin_id: str | None = None
    metadata_filter: BaseModel | None = None
```

`seed_node_ids` 为空时由图向量检索找起点；不为空时，seed 是强制起点，不会被向量结果替换。`query` 始终必填，因为最后一轮局部精排仍要判断候选与当前问题是否相关。每个向量分支最多返回 `vector_top_n` 条；各分支合并成并集池后，最多取 `candidate_limit` 条进入有限遍历和精排。两者分别控制召回宽度和后续工作量。

过滤规则：

- `resource_ids` 与 ACL 是 AND 关系；
- `node_categories` 过滤 Low-Level 节点类别；
- `relation_types` 过滤允许遍历的关系谓词；
- `direction` 支持 `IN`、`OUT`、`BOTH`；
- `max_depth=0` 只处理 seed 或向量直接命中的图元，不向邻接图扩展；
- metadata 过滤必须由垂类插件的 `DeclarativeMetadataFilter` 校验并编译，只允许下推该插件写入来源投影的文档级 metadata 标量字段；不支持 Chunk metadata、任意 JSON 路径或跨字段逻辑。

## 3. Low、High、Hybrid

### 3.1 Low-Level

```text
Query
  -> graph_node_vectors Dense Top-N
  -> node_id 去重
  -> Neo4j 按方向、关系类型和深度有限遍历
  -> 收集命中节点、关系及其来源信息
```

Low 适合具体实体、算法细节和直接依赖问题。不做 PPR；`max_depth` 只是有限遍历深度。

### 3.2 High-Level

```text
Query
  -> graph_edge_vectors Dense Top-N + BM25 Top-N
  -> edge_id 并集去重
  -> Neo4j 读取端点和允许的邻接关系
  -> 收集命中关系、节点及其来源信息
```

High 适合演化路线、方法比较、引用主题等没有单一实体起点的问题。

### 3.3 Hybrid

Hybrid 并行执行 Low 和 High：节点按 `node_id` 去重，关系按 `edge_id` 去重。节点 Dense、关系 Dense 和关系 BM25 属于不同索引空间，不能直接相加原始分数。每个分支先保持 Qdrant 返回的相似度顺序，再按 LightRAG 的 local/global 交替顺序合并；重复图元保留第一次出现的位置。

## 4. 两种调用入口

### 4.1 Query-only

```text
Query
  -> 按 level 查询节点/关系 collection
  -> collection 内去重和 ACL/metadata 预过滤
  -> Neo4j 有限遍历
  -> 分流处理 LLM 图元和确定性图元
  -> 沿用向量和有限遍历的候选顺序
  -> reranker + 相关性门控
  -> Top-K
```

### 4.2 Seed-node + Query

传入 `seed_node_ids` 时，不再调用节点 collection 替换起点。服务先校验 seed 存在且当前用户可读，再按 `direction`、`relation_types`、`max_depth` 读取邻接图，之后进入与 Query-only 相同的来源分流、粗排和局部精排。

普通混合检索已经在 `ChunkHit.node_ids` 中披露当前命中 Chunk 抽取出的实体节点 ID，调用方可以直接将这些 ID 作为下一次图谱检索 seed。

## 5. 两类图元的回查规则

### 5.1 LLM 抽取图元

LLM 图元必须关联一个或多个 `TextGraphEvidence`。Neo4j 命中后批量取得 Evidence ID，再从 Mongo 批量回查：

```text
LLM GraphNode / GraphEdge
  -> TextGraphEvidence IDs
  -> 当前 resource + content_revision 校验
  -> 当前 ResourceAcl.can_read
  -> DocChunk 批量回查
  -> source_spans 从 Document.raw_content 重建 quote
```

以下任一条件失败，该 Evidence 和只由它支持的图元都不能进入结果：

- Evidence 不属于当前 applied revision；
- 当前用户无权读取资源；
- Chunk 不存在或不属于同一 revision；
- `source_spans` 无法重建完全一致的 `quote_text`；
- Evidence 指向的节点或关系不存在。

多个 LLM Evidence 回到同一个 Chunk 时按 `chunk_id` 去重。最终送入 reranker 的是标题路径和权威 Chunk 正文，不是图节点描述、关系描述或 quote 的缓存副本；Top-K 直接返回该可读 Chunk 文本、`resource_id`、`section_id`、`section_path` 和分数，不要求调用方再按 Chunk 指针回查正文。

### 5.2 确定性 producer 图元

确定性 producer 只接收已注册的强类型输入，在生成时完成：

1. metadata 类型校验；
2. 记录必填字段和稳定身份校验；
3. Ontology 实体类别、关系谓词和端点约束校验；
4. 稳定 node/edge ID 计算。

通过后直接写入图元及图索引。写入上下文保存 `resource_id`、`content_revision` 和 `producer_id`，用于 active、删除和 ACL 过滤；这些是图元投影的生命周期字段，不是 Evidence，也不需要 resolver。

查询命中确定性图元时只做当前状态检查：

```text
Deterministic GraphNode / GraphEdge
  -> resource + content_revision 仍为 applied
  -> 当前 ResourceAcl.can_read
  -> 使用图元端点、谓词、description 和已投影字段形成排序文本
```

不重新读取 metadata 来证明 producer 曾经读取过它。如果源 metadata 变化，会产生新的 content revision 和新的确定性图投影；active 切换后旧投影自然不可见。来源投影的 `get_fact_text()` 统一生成精排和 Top-K 展示文本，结果直接返回 `resource_id`、事实文本和分数，不暴露 `producer_id`、revision 或图元 ID。

如果同一稳定关系既被确定性 producer 生成，又被 LLM 从正文抽取，二者可以合并为同一个图身份，但保留两条来源路径：确定性图元本身可以返回，LLM Evidence 仍可额外返回对应 Chunk。不能因为已有确定性来源就放松 LLM quote 校验。

## 6. 粗排和局部精排

图谱检索不能把无界的全图结果送进 reranker。粗排候选分为：

- LLM 路径解析出的当前可读 Chunk；
- 当前可读的确定性节点或关系事实。

粗排规则与 LightRAG 的结果组织方式一致：

1. Low 保留节点 Dense 的向量顺序；High 将关系 Dense 和 BM25 按各自顺序交替合并；Hybrid 再将 Low 与 High 交替合并。
2. 各分支只按逻辑 `node_id` 或 `edge_id` 去重，重复图元保留第一次出现的位置，不融合不同 collection 的原始分数。
3. Neo4j 只在这些有界起点上做 `max_depth` 范围内的批量邻接读取；直接命中排在对应向量命中之后，后续邻接结果按遍历批次追加。
4. LLM 路径按 `chunk_id` 去重；确定性路径按稳定 node/edge ID 与来源投影去重。
5. 并集池和图遍历最多保留 `candidate_limit` 条进入 Common `RankingPipeline`；`top_k` 只控制最终返回数量。

Reranker 文本：

- Chunk 候选使用 `section_path + raw_text`，不带 keywords 或 contextualize prefix；
- 确定性图事实使用端点名称、关系谓词和 producer 已写入的事实描述，不调用 LLM 生成摘要，也不冒充原文。

相关性门控为 `IRRELEVANT` 时返回空结果，`UNCERTAIN` 原样交给上层。通过门控的 Chunk 可以继续构建不截断的动态父块；确定性图事实没有 Chunk，不构建父块。

最终 Top-K 可以同时包含 LLM 正文与确定性图事实。二者均以 `GraphSearchHit` 返回；仅 LLM 正文具有 `section_id` 和 `section_path`，确定性事实不暴露来源投影或生命周期字段。

## 7. ACL 和版本边界

ACL 在 Qdrant/Neo4j 中作为预过滤；候选资源集合确定后，application 按资源批量读取一次本地 ACL，形成本次请求的权限快照：

```text
Qdrant 预过滤
  -> Neo4j 图元/邻接预过滤
  -> LLM 路径：Evidence、Chunk 和 active revision 回查
  -> 确定性路径：图元资源/revision 与 active 状态回查
  -> 使用同一份 ACL 快照决定最终返回
```

Qdrant 和 Neo4j 中的 ACL 都只是减少不可见候选。最终权限事实来自候选资源集合确定后读取的 RAG 本地 `resource_acls`。ACL 更新与索引同步允许存在短暂传播延迟；ACL 缺失仍然 fail-closed。查询中不重复读取同一批 ACL，因为重复本地 IO 不能解决尚未传播到 RAG 的上游变化。

全局合并的节点或关系可能由多个资源产生。查询时只保留当前用户可读、revision 仍 active 的来源；不能因为同一图身份还有一个可读来源，就把另一个不可读来源的 Chunk 或垂类字段一起返回。

## 8. 论文确定性引用示例

这个示例只展示方法：垂类定义 metadata、Ontology 和确定性 producer，直接生成一条 `CITES` 关系。论文不是通用模型的一等公民。

### 8.1 强类型 metadata

```python
class PaperReference(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    reference_id: str
    title: str
    doi: str | None = None
    year: int | None = None


class PaperDocMetadata(DocumentMetadata):
    model_config = ConfigDict(extra="forbid", frozen=True)

    document_type: Literal["paper"] = "paper"
    title: str
    doi: str | None = None
    year: int | None = None
    references: tuple[PaperReference, ...] = ()
```

`references` 来自论文解析器的确定性输出。`reference_id` 是当前 metadata 记录的稳定身份；不要求同一引用字符串还出现在 Markdown 中。

### 8.2 Ontology

```python
AcademicCitationOntology = Ontology(
    domain="academic_citation",
    entity_specs={
        "paper": EntitySpec(
            category="paper",
            description="库内论文或外部被引用论文",
            node_type=GraphNodeKind.EXTERNAL_RESOURCE,
        ),
    },
    relation_specs={
        "CITES": RelationSpec(
            relation_type="CITES",
            description="起点论文在参考文献中引用终点论文",
            allowed_sources=("paper",),
            allowed_targets=("paper",),
        ),
    },
)
```

当前入库论文节点使用 `RESOURCE`，尚未入库的被引论文使用 `EXTERNAL_RESOURCE`。

### 8.3 producer

```python
def produce_citations(document: Document) -> tuple[tuple[GraphNode, ...], tuple[GraphEdge, ...]]:
    metadata = document.metadata
    if not isinstance(metadata, PaperDocMetadata):
        return (), ()

    source = paper_node(metadata.title, metadata.doi, kind=GraphNodeKind.RESOURCE)
    nodes = {source.node_id: source}
    edges: list[GraphEdge] = []

    for reference in metadata.references:
        target = paper_node(
            reference.title,
            reference.doi,
            kind=GraphNodeKind.EXTERNAL_RESOURCE,
        )
        edge = GraphEdge(
            edge_id=graph_edge_id(
                source_node_id=source.node_id,
                relation_type="CITES",
                target_node_id=target.node_id,
            ),
            source_node_id=source.node_id,
            target_node_id=target.node_id,
            relation_type="CITES",
            description=f"{metadata.title} cites {reference.title}",
            keywords=["citation", "reference"],
        )

        AcademicCitationOntology.validate_node(target)
        AcademicCitationOntology.validate_edge(edge, {**nodes, target.node_id: target})
        nodes[target.node_id] = target
        edges.append(edge)

    return tuple(nodes.values()), tuple(edges)
```

写入这批图元时，图谱构建上下文统一附加：

```text
resource_id = document.resource_id
content_revision = document.revision.content_revision
producer_id = paper_metadata_citation_v1
```

没有 `PaperCitationMetadataEvidence`，没有 `evidence_type`，也没有 `PaperCitationEvidenceResolver`。metadata 类型、记录和 Ontology 已在 producer 中校验；引用关系直接成为确定性图事实。

### 8.4 检索

```text
seed paper node
  -> Neo4j 按 OUT + CITES + max_depth=1 读取关系
  -> 只保留当前 active revision 和可读资源的确定性边
  -> 按有限遍历返回顺序，用 source title + CITES + target title + description 进入 reranker
  -> Top-K 确定性图事实
```

如果 LLM 还从正文引用段落抽取出同一条关系，它的 `TextGraphEvidence` 会额外回到 Chunk；这不改变确定性关系可以独立成立的事实。

### 8.5 metadata 过滤

插件只投影真实需要查询的字段。例如首期支持引用年份：

```python
class PaperGraphFilter(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    reference_year_from: int | None = None
    reference_year_to: int | None = None
```

插件在写入时从 `PaperReference` 生成已注册的年份过滤投影，查询时由过滤编译器将 `PaperGraphFilter` 投影到 Qdrant 和 Neo4j。没有查询需求的 DOI、作者等字段留在强类型论文 metadata 中，不塞进通用图元，也不提前扩张过滤契约。

## 9. LightRAG 参考范围

参考 HKUDS/LightRAG commit `09f8249fdd998585fc976b86f7b2e2d5523d9db9`。复用的是方法：实体索引使用名称、描述和别名；关系索引使用端点、关键词和描述；local/global/hybrid 对应节点路径、关系路径和两路合并；图元命中后只处理有限候选，再做局部 rerank。

不复用 `neo4j-graphrag` SDK、LightRAG 存储类型、LLM 输出协议、PPR、贡献聚合或面向生成答案的 token 截断。

## 10. 验收标准

- 只有 `graph_node_vectors` 和 `graph_edge_vectors` 两个图谱专用 Qdrant collection。
- Low 只走节点 Dense；High 走关系 Dense + BM25；Hybrid 并行两路并集。
- Query-only 和 seed-node + Query 都支持，seed 不会被向量检索替换。
- LLM 抽取的每个返回图元都有可回读的 TextGraphEvidence；quote、Chunk、revision 或 ACL 校验失败时不返回。
- 确定性 producer 从强类型事实直接生成图元，不创建 metadata Evidence、Evidence 类型或 resolver。
- 确定性图元保存资源、revision 和 producer 的生命周期投影，并按 active revision 与 ACL 过滤。
- 各分支独立取 Top-N，不直接相加跨 collection 分数，不做 PPR、贡献聚合或 MMR。
- 各向量分支和 Neo4j 遍历均有界；候选沿用 LightRAG 的分支/遍历顺序进入局部精排，不全量扫描图谱。
- Chunk 的 reranker 输入只含标题和 `raw_text`；确定性图事实使用图元自身的稳定事实文本。
- 最终 Top-K 统一返回 `GraphSearchHit`：LLM 正文可附带 Section 定位，确定性事实只返回资源、文本和分数。
