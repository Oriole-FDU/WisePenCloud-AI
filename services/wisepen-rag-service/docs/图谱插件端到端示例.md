# 图谱插件端到端示例

本文用一个很小的“课程目录”垂类说明插件如何接入 RAG 图谱。示例只包含两类实体和一类关系：

- `course`：课程；
- `instructor`：教师；
- `TAUGHT_BY`：课程由教师授课。

重点是插件边界，不是把课程做成 RAG 的通用模型。通用 RAG 只知道 `Document`、图节点、图边和来源 revision；课程字段、Ontology 和过滤字段都由插件提供。

## 1. 定义垂类 metadata

课程目录的来源系统已经把课程和教师关系整理成结构化记录。这个事实不需要再让 LLM 从 Markdown 猜测，也不要求它必须出现在正文中。

```python
from pydantic import BaseModel, ConfigDict

from rag.application.document.models import DocumentMetadata


class CourseMetadata(DocumentMetadata):
    model_config = ConfigDict(extra="forbid", frozen=True)

    document_type: str = "course_catalog"
    course_code: str
    course_title: str
    department: str
    instructor_name: str
    academic_year: int
```

上游准备文档时把它放进 `Document.metadata`：

```python
await document_preparer.prepare(
    resource_id="catalog-2026-spring-cs101",
    document_version=1,
    markdown="# CS101\n\n课程介绍……",
    metadata=CourseMetadata(
        course_code="CS101",
        course_title="程序设计基础",
        department="computer_science",
        instructor_name="张老师",
        academic_year=2026,
    ),
)
```

metadata 是文档 revision 的一部分。字段变化必须产生新的 `document_version` 和 `content_revision`，不能在同一 revision 中覆盖旧 metadata。

## 2. 定义 Ontology

Ontology 只描述这个垂类允许出现什么节点和关系，以及关系两端允许是什么类别。

```python
from rag.application.graph.models import (
    EntitySpec,
    GraphNodeKind,
    Ontology,
    RelationSpec,
)


CourseOntology = Ontology(
    domain="course_catalog",
    description="课程目录中的课程与授课教师关系",
    entity_specs={
        "course": EntitySpec(
            category="course",
            description="一门课程",
            default_node_type=GraphNodeKind.RESOURCE,
        ),
        "instructor": EntitySpec(
            category="instructor",
            description="授课教师",
            default_node_type=GraphNodeKind.ENTITY,
        ),
    },
    relation_specs={
        "TAUGHT_BY": RelationSpec(
            relation_type="TAUGHT_BY",
            description="课程由教师授课",
            allowed_sources=["course"],
            allowed_targets=["instructor"],
        ),
    },
)
```

如果 producer 生成了未知类别、未知关系，或把 `instructor` 放在关系起点，Ontology 校验会拒绝这条图事实。

## 3. 写确定性 producer

producer 消费已经校验过的 `CourseMetadata`，计算稳定节点 ID 和关系 ID。它不创建 Evidence，因为来源事实已经是结构化 metadata 的确定性转换。

```python
from rag.application.document.models import Document
from rag.application.graph.models import (
    GraphEdge,
    GraphNode,
    graph_edge_id,
    graph_node_id,
)


class CourseCatalogProducer:
    producer_id = "course-catalog-v1"

    def produce(self, document: Document):
        metadata = document.metadata
        if not isinstance(metadata, CourseMetadata):
            return (), ()

        course_id = graph_node_id(
            category="course",
            name=metadata.course_code,
        )
        instructor_id = graph_node_id(
            category="instructor",
            name=metadata.instructor_name,
        )
        course = GraphNode(
            node_id=course_id,
            name=metadata.course_title,
            category="course",
            description=f"课程代码：{metadata.course_code}",
            extra_meta={"course_code": metadata.course_code},
        )
        instructor = GraphNode(
            node_id=instructor_id,
            name=metadata.instructor_name,
            category="instructor",
        )
        edge = GraphEdge(
            edge_id=graph_edge_id(
                source_node_id=course_id,
                relation_type="TAUGHT_BY",
                target_node_id=instructor_id,
            ),
            source_node_id=course_id,
            target_node_id=instructor_id,
            relation_type="TAUGHT_BY",
            description=f"{metadata.course_title} 由 {metadata.instructor_name} 授课",
        )
        CourseOntology.validate_node(course)
        CourseOntology.validate_node(instructor)
        CourseOntology.validate_edge(
            edge,
            {course.node_id: course, instructor.node_id: instructor},
        )
        return (course, instructor), (edge,)
```

producer 的输出会被 RAG 包装成两个来源投影：

```text
GraphNodeProjection / GraphEdgeProjection
  resource_id      = catalog-2026-spring-cs101
  content_revision = 当前 Document revision
  producer_id      = course-catalog-v1
  evidence_ids     = 空
```

这里没有 `TextGraphEvidence`，也没有“从 metadata 回溯原文”的步骤。课程与教师关系的证据就是上游结构化课程记录本身。

## 4. 注册 GraphPlugin

插件把四件事放在一起：它匹配哪一种 metadata、使用哪套 Ontology、是否有确定性 producer、哪些 metadata 字段允许作为查询过滤条件。

```python
from rag.application.graph.models import GraphPlugin


course_plugin = GraphPlugin(
    plugin_id="course-catalog",
    metadata_type=CourseMetadata,
    ontology=CourseOntology,
    deterministic_producer=CourseCatalogProducer(),
    enable_llm_extraction=False,
    metadata_filter_values=lambda document: {
        "department": document.metadata.department,
        "academic_year": document.metadata.academic_year,
    },
    filter_compiler=CourseFilterCompiler(),
)
```

容器只装配已注册插件：

```python
container.graph_plugins.override([course_plugin])
```

`GraphFactBuilder.build(resource_id="catalog-2026-spring-cs101")` 的实际路径是：

```text
active Document
  -> metadata 类型匹配 CourseMetadata
  -> CourseCatalogProducer.produce()
  -> Ontology 校验
  -> Mongo graph_node_projections / graph_edge_projections
```

如果文档是 `GeneralDocumentMetadata`，或者没有匹配的插件，构建成功返回空结果，不调用 LLM，也不写图事实。

## 5. 把 metadata 过滤编译成内部条件

API 层可以定义自己的 Pydantic 请求模型；application 不接收自由字典。下面的过滤器只允许按院系和学年过滤：

```python
class CourseFilter(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    department: str | None = None
    academic_year_from: int | None = None
```

编译器把强类型过滤器转换成 RAG 内部的 `GraphFilterCondition`：

```python
from rag.application.retrieval.models import (
    GraphFilterCondition,
    GraphFilterOperator,
)


class CourseFilterCompiler:
    filter_type = CourseFilter

    def compile(self, value: CourseFilter) -> tuple[GraphFilterCondition, ...]:
        conditions = []
        if value.department is not None:
            conditions.append(
                GraphFilterCondition(
                    field="department",
                    operator=GraphFilterOperator.EQ,
                    value=value.department,
                )
            )
        if value.academic_year_from is not None:
            conditions.append(
                GraphFilterCondition(
                    field="academic_year",
                    operator=GraphFilterOperator.GTE,
                    value=value.academic_year_from,
                )
            )
        return tuple(conditions)
```

过滤下推不是把整个 `CourseMetadata` 塞进通用图模型，而是插件明确选择两个真正需要检索的标量字段：

```text
CourseMetadata.department       -> filter_values.department
CourseMetadata.academic_year    -> filter_values.academic_year
CourseMetadata.course_code      -> 不下推，仍只属于 CourseMetadata / 图节点属性
```

图谱投影时，`GraphPlugin.filter_values(document)` 的结果写入 Neo4j 来源投影和 Qdrant payload。查询时同一组 `GraphFilterCondition` 被分别编译为：

```text
Qdrant:
  filter_values.department == "computer_science"
  filter_values.academic_year >= 2026

Neo4j:
  source.filter_values.department = "computer_science"
  source.filter_values.academic_year >= 2026
```

两处过滤只是预过滤，最终仍要检查来源的 `resource_id`、当前 `applied_content_revision` 和 `ResourceAcl.can_read()`。

## 6. 从构建到投影

图事实构建和外部投影是两个独立用例：

```python
await graph_fact_builder.build(
    resource_id="catalog-2026-spring-cs101",
)

await graph_index_builder.index(
    resource_id="catalog-2026-spring-cs101",
)
```

投影输入始终是 Mongo 图事实，不重新调用 producer：

```text
Mongo Graph Facts
  -> Neo4j 逻辑节点、逻辑边和来源投影
  -> graph_node_vectors：节点 Dense
  -> graph_edge_vectors：关系 Dense + BM25
```

本例中的 Qdrant 节点索引文本可以是“程序设计基础、CS101、课程代码……”，关系索引文本可以是“程序设计基础 TAUGHT_BY 张老师……”。`department` 和 `academic_year` 只进入 payload 过滤字段，不冒充正文。

## 7. 一次带过滤的图谱查询

调用方传入强类型过滤器：

```python
from rag.application.retrieval.models import (
    GraphSearchLevel,
    GraphSearchRequest,
)


request = GraphSearchRequest(
    query="2026 年计算机系有哪些课程由张老师授课？",
    level=GraphSearchLevel.HIGH,
    relation_types=["TAUGHT_BY"],
    plugin_id="course-catalog",
    metadata_filter=CourseFilter(
        department="computer_science",
        academic_year_from=2026,
    ),
    top_k=10,
)

result = await graph_retriever.search(request, permission_scope)
```

内部链路是：

```text
CourseFilter 校验
  -> CourseFilterCompiler.compile()
  -> relation Dense Top-N + BM25 Top-N
  -> Qdrant 预过滤 resource / relation_type / ACL / filter_values
  -> edge_id 去重
  -> Neo4j 按 relation_type 和 ACL/filter_values 有界读取
  -> 当前 active revision + 本地 ResourceAcl 快照校验
  -> 关系事实粗排
  -> 沿用向量和有限遍历顺序做局部 rerank
  -> Top-K DeterministicGraphFactHit
```

返回的是确定性图事实，而不是 Evidence：

```python
DeterministicGraphFactHit(
    target_type="edge",
    target_id="ge_...",
    resource_id="catalog-2026-spring-cs101",
    content_revision="catalog-2026-spring-cs101@1#...",
    producer_id="course-catalog-v1",
    rerank_score=0.91,
)
```

如果同一课程关系也被 LLM 从正文抽取，LLM 来源会另外保存 `TextGraphEvidence` 并可能返回 `ChunkGraphHit`；确定性来源仍然可以独立返回，二者不互相替代。

## 8. 如果以后打开 LLM 抽取

只需把插件的 `enable_llm_extraction` 改为 `True`。LLM 抽取仍使用同一套 Course Ontology，但它必须为每个节点和关系提供目标 Chunk 内唯一、逐字匹配的 `quote`；RAG 会据此建立 `TextGraphEvidence`。

因此同一个插件可以同时拥有两条来源路径：

```text
CourseMetadata -> CourseCatalogProducer -> producer_id -> 确定性图事实
Markdown Chunk  -> Instructor LLM     -> quote       -> TextGraphEvidence
```

插件负责垂类事实和规则；RAG 负责 revision、ACL、稳定 ID、Mongo 事实保存、Neo4j/Qdrant 投影以及最终检索排序。这个分工就是插件边界的完整含义。
