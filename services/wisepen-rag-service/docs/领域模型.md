# RAG 重构方案：核心领域模型

本文件从核心领域模型开始，后续章节再讨论索引、检索和服务接口。

本章有三个边界：

1. Common 只提供无业务含义的文档结构事实：`DocumentChunk`、`Section`、`Page`、`Anchor`、`OutlineNode`、`SourceSpan`。RAG 不把 Common 模型直接当作自己的业务契约，而是做一次明确投影。
2. RAG 不保存静态父块。`DocChunk` 是检索原子，较大的阅读上下文在查询时根据 Section 和原文坐标动态装箱。
3. 本章只定义持久化或跨应用服务需要稳定表达的领域事实，不定义 MCP 工具参数，也不定义某个数据库的 payload。

## 1. 内容版本

内容版本是 RAG 唯一需要表达的版本命名空间。结构、切块和图谱证据都建立在同一份 Markdown 字符坐标上；如果实现代码或索引策略变化，直接重建，不再另造 `structure_revision`、`retrieval_revision`、`graph_revision` 或 `profile_id`。

```python
import hashlib

from pydantic import BaseModel, ConfigDict, Field


class ContentRevision(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    resource_id: str
    document_version: int = Field(ge=1)
    content_sha256: str

    @classmethod
    def create(
        cls,
        *,
        resource_id: str,
        document_version: int,
        raw_content: str,
    ) -> "ContentRevision":
        return cls(
            resource_id=resource_id,
            document_version=document_version,
            content_sha256=hashlib.sha256(
                raw_content.encode("utf-8")
            ).hexdigest(),
        )

    @property
    def revision_id(self) -> str:
        return f"{self.resource_id}@{self.document_version}#{self.content_sha256[:16]}"
```

`document_version` 来自上游资源；`content_sha256` 用来确认本次坐标确实对应这份 Markdown。

## 2. 文档结构投影

Common 的 `Section` 真实字段是 `own_span`、`subtree_span` 和 `content_spans`；`Page` 的真实坐标字段是 `source_span`。Common `section_id` 只由 Section 类型和局部 span 计算，只保证在一次内容解析结果中可用，不是 RAG 的全局寻址契约。

RAG 接收 Common 分块结果后，保留 `Section` 类型和全部非业务结构字段，但统一重写 `section_id`：

```python
def rag_section_id(
    *,
    resource_id: str,
    content_revision: str,
    common_section_id: str,
) -> str:
    identity = f"{resource_id}\0{content_revision}\0{common_section_id}"
    digest = sha256(identity.encode("utf-8")).hexdigest()
    return f"rsec_{digest[:24]}"
```

重写必须在一次映射中完成：先计算所有 Common ID 到 RAG ID 的映射，再用 `dataclasses.replace()` 同时替换每个 Section 的 `section_id` 和 `parent_section_id`，最后替换 Common `DocumentChunk.section_id` 后再投影为 `DocChunk`。不能只改 Section 自身而留下旧父 ID 或 Chunk 引用。

`content_revision` 必须参与计算。Common ID 不包含标题或正文；如果同一资源更新后 span 恰好没变，只拼 `resource_id` 会让旧 Section ID 误指向新内容。加入 revision 后，active 切换会自然淘汰旧 ID。

RAG 的 `DocumentStructure` 负责收拢重写后的 Common 结构事实：

```python
from dataclasses import dataclass, field

from common.utils.document import Anchor, Page, Section


@dataclass(slots=True)
class DocumentStructure:
    total_length: int
    sections: list[Section] = field(default_factory=list)
    pages: list[Page] = field(default_factory=list)
    anchors: list[Anchor] = field(default_factory=list)
```

`DocumentStructure` 不再保存结构模式。Common 已经统一分块和坐标行为，RAG 不需要根据“有标题”或“无标题”选择不同的 Chunk/父块构建策略。`sections` 为空只表示没有标题树；`raw_content` 为空表示没有正文。解析异常通过构建失败处理，不伪造 `structure_failed`。

RAG Section ID 是全局、版本化的能力入口。标题树邻域和 Section 读取可以只接收一批 `section_id`，由仓储批量定位对应的 active Document，不再要求调用方按 `resource_id` 拆分请求。

## 3. 元数据

文档元数据和切块元数据分开。它们都使用可辨识联合类型，禁止把未注册字段随意塞进 `dict`。垂类需要增加字段时，新增自己的 metadata 类型和插件，不修改通用 `Document`、`DocChunk` 结构。

```python
from typing import Annotated, Literal, Union

from pydantic import BaseModel, ConfigDict, Field


class BaseDocMetadata(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)


class GeneralDocMetadata(BaseDocMetadata):
    doc_type: Literal["general"] = "general"


class BaseChunkMetadata(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)


class GeneralChunkMetadata(BaseChunkMetadata):
    chunk_type: Literal["general"] = "general"


AnyDocMetadata = Annotated[
    Union[GeneralDocMetadata],
    Field(discriminator="doc_type"),
]

AnyChunkMetadata = Annotated[
    Union[GeneralChunkMetadata],
    Field(discriminator="chunk_type"),
]
```

论文等垂类以后可以声明 `PaperDocMetadata`、`PaperChunkMetadata`，并在插件中声明过滤投影和图谱 Ontology。本阶段不把论文字段写进通用模型。

## 4. `Document` 聚合根

`Document` 是当前已发布资源的权威聚合根。它持有完整 Markdown、结构、内容版本、ACL 和文档级 metadata。Qdrant、Neo4j 和缓存都不能取代它作为原文与结构真值。

```python
from pydantic import BaseModel, ConfigDict, Field


class Document(BaseModel):
    model_config = ConfigDict(extra="forbid")

    resource_id: str
    revision: ContentRevision
    raw_content: str
    structure: DocumentStructure
    acl: ResourceAcl
    metadata: AnyDocMetadata = Field(default_factory=GeneralDocMetadata)
```

约束：`revision.resource_id == resource_id`；`structure.total_length == len(raw_content)`；所有 Section、Page、Anchor 的坐标都必须落在 `[0, len(raw_content)]` 内。Document 不包含删除标记、Kafka offset、检索状态或图谱状态。

## 5. `DocChunk` 检索原子

`DocChunk` 是 Common `DocumentChunk` 的 RAG 业务化投影：它负责检索、向量化、BM25 和局部坐标回查，不负责权限所有权，也不负责保存父块。

```python
from common.utils.document import SourceSpan


class DocChunk(BaseModel):
    model_config = ConfigDict(extra="forbid")

    chunk_id: str
    resource_id: str
    content_revision: str
    chunk_index: int = Field(ge=0)

    # 有真实 Section 时记录直属 Section；没有标题树时保持为 None。
    section_id: str | None = None
    section_path: tuple[str, ...] = ()

    # 权威正文与绝对 Python 字符坐标。
    raw_text: str
    source_spans: tuple[SourceSpan, ...] = Field(min_length=1)
    page_labels: tuple[str, ...] = ()
    anchor_labels: tuple[str, ...] = ()

    # 只保存增强产物；它们不能改变 raw_text 或 source_spans。
    contextual_prefix: str = ""
    key_terms: tuple[str, ...] = ()
    extracted_node_ids: tuple[str, ...] = ()
    metadata: AnyChunkMetadata = Field(default_factory=GeneralChunkMetadata)

    def get_semantic_text(self) -> str:
        """Dense embedding 输入：结构路径、上下文前缀和正文。"""
        parts: list[str] = []
        if self.section_path:
            parts.append(" > ".join(self.section_path))
        if self.contextual_prefix.strip():
            parts.append(self.contextual_prefix.strip())
        parts.append(self.raw_text)
        return "\n\n".join(parts)

    def get_lexical_text(self) -> str:
        """BM25 输入：保留可精确命中的标题、关键词和正文词面。"""
        parts: list[str] = []
        if self.section_path:
            parts.append(" ".join(self.section_path))
        if self.key_terms:
            parts.append(" ".join(self.key_terms))
        parts.append(self.raw_text)
        return " ".join(parts)
```

这两个方法是 `DocChunk` 的领域行为，不是投影字段。Dense/BM25 适配器在调用时即时获得字符串；Mongo 不保存 `semantic_index_text` 或 `lexical_index_text`。重建索引时，从当前 `DocChunk` 的 `section_path`、`contextual_prefix`、`key_terms` 和 `raw_text` 重新调用方法即可。

`chunk_index` 只表示本次 Document 内的稳定顺序，不引入 Chunk Set ID。更新文档会产生新的 `ContentRevision` 和新的 chunk 集合；旧集合按物理清理处理。

## 6. ACL 领域事实

ACL 复用现有 RAG 已验证的判定行为，但不把 Common ACL 模型变成 RAG 契约。权限事实只挂在 `Document`，`DocChunk` 不重复保存 ACL。

```python
from dataclasses import dataclass, field
from collections.abc import Mapping

from common.core.domain import GroupRoleType


@dataclass(slots=True)
class PermissionScope:
    user_id: str
    group_roles: dict[str, GroupRoleType | None] = field(default_factory=dict)

    @classmethod
    def from_group_roles(
        cls,
        user_id: str,
        group_roles: Mapping[str, GroupRoleType | None],
    ) -> "PermissionScope":
        return cls(user_id=user_id, group_roles=dict(group_roles))

    @property
    def managed_group_ids(self) -> set[str]:
        return {
            group_id
            for group_id, role in self.group_roles.items()
            if role in (GroupRoleType.OWNER, GroupRoleType.ADMIN)
        }

    @property
    def joined_group_ids(self) -> set[str]:
        return {
            group_id
            for group_id, role in self.group_roles.items()
            if role is not None and role is not GroupRoleType.NOT_MEMBER
        }


@dataclass(slots=True)
class GroupResourceAcl:
    group_id: str
    default_readable: bool
    readable_users: list[str] = field(default_factory=list)
    excluded_read_users: list[str] = field(default_factory=list)


@dataclass(slots=True)
class ResourceAcl:
    resource_id: str
    acl_revision: int
    owner_id: str
    readable_users: list[str] = field(default_factory=list)
    excluded_read_users: list[str] = field(default_factory=list)
    group_acls: list[GroupResourceAcl] = field(default_factory=list)

    def can_read(self, scope: PermissionScope) -> bool:
        if scope.user_id == self.owner_id:
            return True
        if scope.user_id in self.readable_users:
            return True
        if scope.user_id in self.excluded_read_users:
            return False
        for group_acl in self.group_acls:
            if group_acl.group_id in scope.managed_group_ids:
                return True
            if group_acl.group_id not in scope.joined_group_ids:
                continue
            if group_acl.default_readable:
                if scope.user_id not in group_acl.excluded_read_users:
                    return True
            elif scope.user_id in group_acl.readable_users:
                return True
        return False
```

## 7. 图谱领域模型

图谱空间和文本空间正交：`GraphNode`、`GraphEdge` 不继承 `DocChunk`。LLM 从正文抽取的图元必须关联 `TextGraphEvidence`；确定性 producer 从已校验的强类型事实直接生成图元，不再为了统一形式包装成 Evidence。节点收敛为三态：库内文档资源、外部资源、一般实体。外部资源是后续联网扩展的路标，不等于当前已有正文。

```python
from enum import StrEnum


class GraphNodeKind(StrEnum):
    ENTITY = "entity"
    RESOURCE = "resource"
    EXTERNAL_RESOURCE = "extern_resource"


class GraphNode(BaseModel):
    model_config = ConfigDict(extra="forbid")

    node_id: str
    name: str
    node_type: GraphNodeKind
    category: str
    description: str = ""
    aliases: tuple[str, ...] = ()
    extra_meta: dict[str, object] = Field(default_factory=dict)


class GraphEdge(BaseModel):
    model_config = ConfigDict(extra="forbid")

    edge_id: str
    source_node_id: str
    target_node_id: str
    relation_type: str
    description: str = ""
    keywords: tuple[str, ...] = ()
    extra_meta: dict[str, object] = Field(default_factory=dict)


class TextGraphEvidence(BaseModel):
    """LLM 从权威 Markdown 或 Chunk 抽取图元时必须保存的文本证据。"""

    model_config = ConfigDict(extra="forbid")

    evidence_id: str
    target_type: Literal["node", "edge"]
    target_id: str
    resource_id: str
    content_revision: str
    section_id: str | None = None
    chunk_id: str
    source_spans: tuple[SourceSpan, ...] = Field(min_length=1)
    quote_text: str
```

`TextGraphEvidence` 只服务于非确定性的正文抽取。它的 `quote_text` 必须能按 `source_spans` 从当前 `Document.raw_content` 精确回读；无法回读的 LLM 节点或关系不得入库。

确定性 producer 的输入本身就是强类型事实，例如论文解析器给出的引用记录或作者机构对应关系。producer 在写入前完成 metadata 类型校验和 Ontology 校验，生成的图元直接携带资源、revision 和 producer 所需的最小投影字段。查询时按 active revision 和 ACL 过滤这些图元即可，不创建 metadata Evidence 类型，不注册 Evidence resolver，也不再重复回查同一条 metadata 来“证明”producer 刚刚读取过它。

## 8. Ontology 与垂类扩展点

Ontology 是垂类图谱的核心扩展点，不是论文专属实现。它声明实体类别、关系谓词及端点约束，并为 LLM 抽取和确定性 producer 提供同一套校验规则。

```python
class EntitySpec(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    category: str
    description: str
    default_node_type: GraphNodeKind = GraphNodeKind.ENTITY


class RelationSpec(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    relation_type: str
    description: str
    allowed_sources: tuple[str, ...] = ()
    allowed_targets: tuple[str, ...] = ()


class Ontology(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    domain: str
    description: str = ""
    entity_specs: dict[str, EntitySpec] = Field(default_factory=dict)
    relation_specs: dict[str, RelationSpec] = Field(default_factory=dict)

    def validate_node(self, node: GraphNode) -> None:
        spec = self.entity_specs.get(node.category)
        if spec is None:
            raise ValueError(f"unknown entity category: {node.category}")

    def validate_edge(self, edge: GraphEdge, nodes: Mapping[str, GraphNode]) -> None:
        spec = self.relation_specs.get(edge.relation_type)
        if spec is None:
            raise ValueError(f"unknown relation type: {edge.relation_type}")
        source = nodes[edge.source_node_id]
        target = nodes[edge.target_node_id]
        if spec.allowed_sources and source.category not in spec.allowed_sources:
            raise ValueError("relation source category is not allowed")
        if spec.allowed_targets and target.category not in spec.allowed_targets:
            raise ValueError("relation target category is not allowed")
```

垂类插件可以额外声明：文档 metadata 类型、Chunk metadata 类型、Ontology、确定性 graph producer 和过滤投影。确定性 producer 的输出必须能够直接写入图存储和图索引；不要求额外声明 Evidence 类型或 resolver。论文可以作为示例接入 `author`、`institution`、`CITES` 等事实，但这些字段不进入通用核心模型，也不劫持 RAG 的其他能力。

## 9. 本章完成标准

- `Document` 是唯一权威内容和结构聚合根；只有 `ContentRevision`。
- `DocChunk` 能从 Common `DocumentChunk` 明确投影，且提供 `get_semantic_text()`、`get_lexical_text()`；两个索引输入不持久化。
- `Section`、`Page`、`Anchor`、`SourceSpan` 只按 Common 真实字段复用；RAG 会把 Common 的局部 Section ID 重写为包含资源和 revision 的全局 ID，并同步更新父子及 Chunk 引用。
- ACL 只在 Document 层判定，DocChunk 不复制权限字段。
- GraphNode、GraphEdge 与 DocChunk 正交；LLM 抽取必须通过 TextGraphEvidence 回到 Markdown 坐标，确定性 producer 直接从强类型事实生成图元，不创建 Evidence 包装层。
- Ontology 能约束实体类别和关系端点，垂类 producer 可以通过插件接入。
- 本章没有 MCP 工具 schema、HTTP endpoint、检索结果 DTO、Kafka offset、逻辑删除、静态父块或 Chunk Set ID。
