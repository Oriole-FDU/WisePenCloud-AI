## 4. P2：Chunk 与 IngestionPipeline

### 工作内容

1. 定义 `Document` 和 `Chunk`。Chunk 使用 `metadata: dict[str, object]`，不使用 `ChunkDerivedMetadata` 或 Pydantic schema。
2. `Chunk` 至少包含 resource/revision/chunk identity、section 归属、raw text、token count、anchor labels 和 metadata；同时冻结
   P3 需要的 GraphNode/GraphEdge 字段，不在此实现图谱抽取。
3. `retrieval_text` property 按标题路径（">".join）、非空 contextual_context、raw_text 用空行拼接；不改正文事实。
4. 封装现有 `MarkdownChunker` 为 `Chunker.split(document) -> list[Chunk]`。
5. 定义三个最小 Protocol：

```python
class Chunker(Protocol):
    async def split(self, document: Document) -> list[Chunk]: ...


class Transformer(Protocol):
    async def transform(
        self, chunks: list[Chunk], *, document: Document | None = None,
    ) -> list[Chunk]: ...


class Indexer(Protocol):
    async def index(self, chunks: list[Chunk]) -> None: ...
```

6. 实现 `IngestionPipeline.run(document)`：Chunker 一次调用，Transformers 按序调用，Indexers 按配置顺序串行调用。
7. 允许 Transformer 原地修改 metadata 或返回新 Chunk；Pipeline 始终使用返回值，不自动深拷贝。
8. 保持 Chunk identity、来源、顺序和 raw text 稳定；Indexer 只读，不用 `pop()` 消费 metadata。
9. 开发者固定正确组件组合，保证 Extractor 有对应 Indexer、必需投影 Writer 齐全；不添加运行时装配检查。

### 失败合同

- Transformer 异常：停止后续 Transformer 和所有 Indexer；
- Indexer 异常：停止后续 Indexer，已完成写入保留；
- Pipeline 只有全部阶段成功才返回成功；
- 不提供 rollback、`continue_on_error`、并行调度或统一 failure object；
- 发布和部分索引可见性由外部 capability 决定。

### 验收门槛

- 使用 fake Chunker/Transformer/Indexer 完成完整 pipeline 测试；
- 验证完整 list 输入、返回值传递、原地 metadata 修改和 identity 稳定；
- 验证 Transformer/Indexer fail-fast；
- 用固定应用流程的行为测试验证事实与必需投影顺序，不增加装配校验测试；
- 验证普通 pipeline 不依赖 GraphExtractor、GraphIndexer 或任何数据库。

## 5. P3：VectorStorage、GraphStorage 和过滤

### 工作内容

1. 定义 Reader/Writer Protocol，同一个具体 Adapter 可以实现两者。
2. 定义统一 `VectorRecord`、`VectorQuery`、`VectorMatch`。Chunk、Entity、Relationship 只在投影时转换为 VectorRecord。
3. 定义 collection-bound `VectorStorage`；Record 不携带 namespace。
4. 定义 `GraphStorage`，直接使用 `GraphNode`、`GraphEdge`，提供节点、关系、邻接和有界遍历原语。
5. 将 Transformer 产出的 Chunk（含图谱 metadata）持久化到现有 Mongo Chunk 内容事实集合；不增加 GraphFactStore 或
   GraphChunkSource 集合。
6. 定义通用 `MetadataFilters`。plugin 负责把垂类请求过滤编译为通用条件，Storage 只执行。
7. 实现 fake storage contract，再实现 Qdrant/Neo4j adapter 的最小读写方法。

### 不做

- Storage 不理解 ACL、active revision、Chunk 生命周期或 local/global/hybrid；
- 不增加 Repository、Storage Router 或跨存储事务；
- 不把 Cypher、Qdrant 查询字段或业务 request 下沉到 Storage。

### 验收门槛

- VectorStorage 批量 upsert/query/delete 通过；
- GraphStorage 节点、关系、邻接和 bounded traversal 通过；
- collection 由 Storage 实例绑定；
- MetadataFilters 的 plugin 编译和 adapter 翻译通过；
- fake storage 不需要 ACL、HTTP request 或 active revision 即可通过 contract。

## 6. P4：Contextual、VectorIndexer 和普通检索

### 工作内容

1. 已实现 `Contextualizer.transform(chunks, *, document=...)`，只修改
   contextual_context/context_status/context_version；非空输入要求匹配 Document。
2. 统一 TokenCounter 对完整提示文本计数，默认 8000 token；选择全文、最高可容纳祖先子树、own/目标种子和连续 Chunk 窗口，允许跨
   section，不跨 resource/revision。纯标题大纲有独立上限；每侧加入邻居前实际重新计数提示词。
3. contextual 不修改 raw text、Chunk identity 或图谱事实归因。
4. 实现 `VectorIndexer.index(chunks)`：选择 `retrieval_text`、生成 embedding、构造 VectorRecord、调用 VectorWriter。
5. 通过 ContentWriter 保存 Document，并由 ChunkFactsIndexer 保存 Transformer 返回的完整 Chunk；MongoContentStorage
   实现两个内容集合的批量读写，不另加 Repository 或通用 Mongo 框架。普通 metadata 随 Chunk 保存，仍不增加 metadata schema 或
   codec。
6. 实现无请求状态的 RAG Qdrant Dense/Sparse Retriever adapter；用 Common `Candidate`、`FusionRetriever` 和显式
   `RoundRobinFusion`/`RrfFusion` 做候选组合。组件只保存固定依赖与配置，retrieve (query: str) 只接收查询文本；预算、filters
   和 include_embedding 在初始化时确定，默认 RoundRobin，可注入 RRF；Common `BM25Retriever` 是对内存 Candidate 列表建索引，不作为
   Qdrant sparse adapter。
7. 上层 application 每次独立能力调用创建 ResourceSnapshot，VectorRetrieval 显式接收并复用快照；用例持有固定 VectorReader
   与已绑定模型/维度的 EmbeddingClient，直接通过 VectorRetriever.from_storage 选择 dense/sparse/hybrid（默认
   hybrid），按本次预算、filters、diversity 装配召回组件与 Common Pipeline。prepare_candidates 批量调用
   ResourceSnapshotReader.read_chunks，并核对向量 resource/revision 与 Chunk 身份。只有授权且属于 selected revision
   的正文进入重排；MMR 使用候选已存向量。统一 Candidate[PreparedChunk] 映射为 ChunkHit，授权过滤后不补召回。混合检索用例与
   Retriever 分开，快照不绑定 Retriever constructor。
8. 接受并测试 Common RetrievalPipeline 的重排失败降级：保留重排前顺序与分数；召回、准备与多样化异常直接传播。
9. 图谱不可用时，Chunk hybrid retrieval 仍然独立工作。
10. 接入 Document/Chunk Mongo 事实写入和普通检索发布条件；提供直接内容读取、section、outline/neighborhood 的业务入口，共用
    selected revision 与 ACL，不增加 HTTP 路由。

### 验收门槛

- context 缺失时 retrieval_text 为标题路径加原文；路径也为空时才等于 raw_text；
- context 只改变 embedding/检索文本，不改变 Chunk identity；
- 模型/输出异常逐块降级，程序/结构错误传播；成功指纹匹配跳过 LLM，失败与过期可重算；实例级模型并发限制不污染文档调用；
- 离线 repair 显式资源范围，选当前 applied 未 destroyed revision，核对正文身份与写前状态；全部 Chunk 向量每次重写，失败可重跑；不
  stage/apply、不重新分块；
- Dense、Qdrant sparse、显式 Fusion、selected revision/ACL 回查、授权正文 rerank 和 `Candidate[PreparedChunk] -> ChunkHit`
  转换形成闭环；
- staged 内容只有 Mongo 事实和 Chunk 向量完整后才发布；直接读取与 outline 无权/旧版本时不返回正文；
- 旧 revision 候选无法混入当前请求；
- 图谱组件完全不启动时普通检索仍通过。

## 9. P7：Chunk 种子、候选节点（父块暂缓）

### 工作内容

1. 普通 Chunk 检索结果直接从已授权 Chunk metadata 生成轻量 Entity `GraphNodeReference`。
2. `ChunkHit.seed_entities` 只表示候选，不表示已经选中的 seed。
3. 调用方选出的逻辑 node ID 由 traversal 从当前合法可见来源再次确认 resource、revision、ACL 和事实来源，不要求原 ChunkHit
   锚定。
4. 只对确认过可见来源的 node ID 调用 GraphReader.get_neighbors，不自动遍历未选择候选。
5. GraphTraversal 只提供一跳、可选方向和谓词约束，不提供 depth；后续跳由调用方重新选择种子。
6. 父块构建暂缓，本轮不预建展开参数、后处理接口或结果字段。
7. 节点候选补充失败时返回普通 ChunkHit，候选列表为空；响应层的空值移除仍由外部处理。

### 验收门槛

- Chunk hybrid retrieval 不依赖图谱才能返回；
- 模型未选中的候选不会自动进入 traversal；
- 旧 revision 或仅隐藏来源支持的 seed 不能扩展；不同可见文档可经共享逻辑实体连接；
- 没有图谱 metadata 的 Chunk 仍是有效普通结果；
- 父块范围暂缓，不作为本阶段验收门槛。
