## 1. Agent 可编排的 RAG 工具链

传统 RAG 通常把 RAG 视作一条封闭的“检索—反思—生成”流水线：模型机械执行检索，拿到上下文后直接回答。我们的 Agent 平台把 RAG 视作一组可独立调用的原子工具：文档检索、图谱检索、Section 阅读、标题树导航、原文回溯和证据核验都可以单独使用。

Agent 掌握任务主导权，可以随时进入 RAG、在多个工具之间穿插调用，并根据中间结果反复使用 RAG：

```text
RAG 找线索 → 调用其他工具行动 → 产生新问题/新实体
       → 再次进入 RAG 补充信息 → 验证结论 → 继续行动
```

RAG 因此不再是一次性问答流程，而是 Agent 在整个任务周期内可反复进入的知识能力。

## 2. 检索与阅读分离：检索要精确，阅读要完整

这是整个系统的核心设计思想。

**检索阶段追求精确命中。** 文档被切成较小的子块，分别建立 Dense 向量索引和 BM25 关键词索引。Dense 擅长理解语义相似的问题，BM25 擅长匹配专有名词、编号和精确术语；两路结果融合后，尽可能准确地找到真正相关的句子和段落。

**阅读阶段追求完整语境。** 子块命中后不直接把孤立片段交给模型，而是回到 Section 边界，根据命中范围动态恢复父块：短文本直接取完整 Section；中文本在覆盖率高时取 Section；长文本或覆盖率不足时构造连续阅读窗口。同时利用标题树的父子、前后和兄弟关系补充邻域上下文。

这样既避免“大段全文搜索”带来的噪声，又避免“只读命中句子”造成语义断裂：**检索要精确，阅读要完整。**

## 3. 文档基座 + 图谱基座双引擎

系统以 **Section 为主要知识单元**，同时建设两套互补的知识基座：

- **文档基座**：保存 Markdown、Section、Chunk、页码、标题路径和原文坐标。它负责精确找到原文、恢复完整上下文，并支持 Dense/BM25 混合检索。
- **图谱基座**：保存实体、关系、Chunk 和 Document 的连接。Qdrant 中建立 Entity/Relation 向量，Neo4j 中保存关系拓扑；它负责回答“哪些对象有关”“沿关系还能走到哪里”和“哪些原文支撑这条路径”。

文档基座擅长找原文，图谱基座擅长做关系推理与多跳扩展；两者通过 Chunk、Section 和原文坐标连接起来。

## 4. 混合检索驱动的多跳推理闭环

这是区别于普通文档问答的关键能力：图谱检索不必等待用户预先提供实体，也不依赖一次固定的图谱入口，实体可以由文档混合检索动态发现。

```text
用户问题
   │
   ▼
文档混合检索（Dense + BM25）
   │
   ├── 命中相关 Chunk
   ├── 聚合所属 Section
   └── 从原文发现实体 A、实体 B
                    │
                    ▼
          以 A / B 作为图谱种子
                    │
                    ▼
             Neo4j 多跳拓扑扩展
          A ──关系1──> C ──关系2──> D
                    │
                    ▼
       发现跨章节实体、依赖、演化和对比路径
                    │
                    ▼
             反查路径对应的原文 Chunk
                    │
                    ▼
          Section 边界 + 标题树邻域阅读
                    │
                    ▼
            Rerank 精排 + 去重 + 证据组装
                    │
                    ▼
        Agent 推理 / 调用其他工具 / 再次 RAG
```

这个闭环把“文本召回”和“结构推理”连接起来：先从文档中找到问题相关的实体，再让实体进入图谱进行多跳推理，最后回到原文验证每一步推理是否有依据。

## 5. 证据可回溯、可核验

系统中的检索结果、实体、关系和推理路径都保留来源信息，不只返回一段无法解释的生成文本。每条结论都可以回到：

- **Section**：结论属于哪一个章节主题；
- **Chunk**：哪一个精确检索单元命中了问题；
- **页码与原文坐标**：结论在原始 Markdown 或页面中的具体位置；
- **标题路径**：该段内容在文档层级中的上下文；
- **图谱路径**：实体之间经过了哪些关系和跳数；
- **Evidence**：支撑实体、关系或结论的连续原文片段。

因此，Agent 可以先用紧凑的检索结果进行推理，再按需回溯 Section 和 Evidence 完成核验；最终答案既有相关性，也有清晰的证据链。

## 总结：五点能力如何形成 Agent 闭环

```text
原子化 RAG Tools
        │
        ├── 文档混合检索：精确找 Chunk
        ├── 父块与标题树：恢复完整阅读语境
        ├── 图谱 Low / High / Hybrid：发现关系并多跳扩展
        ├── 文档基座 + 图谱基座：文本与结构协同
        └── Section / Chunk / 页码 / 路径 / Evidence：全程可核验
        │
        ▼
Agent：检索 → 发现实体 → 多跳推理 → 原文核验
      → 调用其他工具 → 产生新问题 → 再次 RAG
```

我们的 RAG 不是 Agent 外部的一条固定问答流水线，而是 Agent 可以自由编排、穿插调用和循环使用的知识工具链。
